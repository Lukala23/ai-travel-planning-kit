# AI 旅行规划工具包（AI Travel Planning Kit）

## 让 AI 帮你查资料、选住宿、排路线、控预算，并生成真正能照着执行的完整旅行方案

**AI 旅行规划工具包**是一套可以直接交给 AI 使用的开源规划文件。你只需要告诉 AI 这次去哪、什么时候去、几个人、大致预算和不能妥协的要求，它就会按一套更完整的规则帮你：

- 搜集并核验目的地的最新信息；
- 判断哪些地方真正值得去，哪些只是营销很强；
- 比较住宿区域和具体酒店；
- 把景点、吃饭、交通、休息和住宿排成能走通的路线；
- 提前处理支付、网络、换汇、税费、小费、骗局和语言问题；
- 按需要补充博物馆、摄影、自驾、徒步和出境建议；
- 最后交付完整攻略、手机速查版、图片指引和出发前更新清单。

它不是一个替你下单的旅行 App，也不是一份固定攻略。它更像一套给 AI 使用的“旅行规划工作说明”：告诉 AI 应该查什么、怎样比较、哪些信息必须现查，以及最终怎样把结果整理得方便你执行。

你的偏好都可以自行增加、删除或修改；目的地、日期、人数、预算和旅行方式则在每次出行时重新提供，不会被写死。

## 你可以用它完成什么

```mermaid
flowchart LR
    A["告诉 AI 本次出行信息"] --> B["查最新资料并筛选候选"]
    B --> C["比较住宿、交通、餐饮与预算"]
    C --> D["生成逐日可执行路线"]
    D --> E["输出完整攻略与手机速查版"]
    E --> F["出发前按天气和运营状态更新"]
```

例如，你可以直接说：

> 我们两个人 10 月去日本关西 7 天，从上海往返，预算 2 万元左右。第一次去，希望经典景点和真正值得的小众体验都兼顾，不自驾。请先帮我判断住在哪里、怎样分配城市和天数，再生成完整路线。

工具包会要求 AI 先确认真正影响方案的条件，再研究住宿区域、跨城交通、景点价值、餐饮、支付与预约，最后形成一套彼此衔接的方案，而不是立刻拼出一张看似丰富的景点表。

## 核心功能与卖点

| 功能 | 实际会帮你解决什么 |
|---|---|
| 目的地与景点筛选 | 同时寻找经典和小众体验，分析真实旅行价值，识别刷分、网红营销和高热度低体验地点 |
| 完整行程安排 | 把门到门交通、排队、吃饭、休息、行李、预约和返回时间算进每天，而不只排列景点 |
| 住宿重点规划 | 先选适合的住宿区域，再比较具体酒店的总价、交通、夜间闲逛、周边饮食、噪声和住宿体验 |
| 在地饮食安排 | 寻找本地人真实日常选择，把值得吃的餐馆、小店和市场顺路排进每天，不照搬网红榜单 |
| 预算与费用控制 | 统一币种和计价口径，拆分住宿、交通、门票、餐饮和可选体验，标出税费、押金与容易漏算的成本 |
| 交通、支付与网络 | 核验交通票制、手机支付、银行卡、本地钱包、现金、换汇、SIM / eSIM、漫游及支付失败备份 |
| 打车、包车与防骗 | 给具体路段的正常价格范围、正规渠道、议价和书面确认话术，并预警加价、币种偷换和扣留行李等风险 |
| 出境旅行辅助 | 整理签证与入境、正式收费、服务费、小费习惯、当地特殊情况、语言标识和一张简洁的境外安全提示卡 |
| 博物馆与中文理解 | 判断大小博物馆的真实参观价值、当前展览、中文讲解、是否值得请中文导游，以及具体馆内动线 |
| 手机摄影建议 | 为核心景点和常规景点给站位、朝向、构图、人物位置、光照与参考图；高成本拍摄只作为可选强化方案 |
| 徒步与户外保障 | 审核你提供的轨迹，并重点检查许可、天气、保险、医疗、通信、山屋、饮水、装备、退出与救援条件 |
| 清晰的最终交付 | 从同一份内容生成完整 Markdown、可搜索 PDF、手机速查卡、必要图片和按需打印的应急版 |

## 它和一段普通提示词有什么不同

- **会重复使用**：安装一次，以后每次只需提供新的目的地和本次条件。
- **会按旅行类型加载规则**：城市观光、度假、出境、自驾、博物馆和徒步可以自由组合，不要求固定顺序。
- **会把各部分一起规划**：住宿不是附加榜单，饮食不是文末推荐，交通也不是一句“坐地铁”。它们共同决定路线和预算。
- **会要求现查动态信息**：票价、开放、班次、天气、签证、道路、步道、支付和库存都要按本次日期联网核验。
- **会说明不确定性**：查不到、来源冲突或必须临近出发复查时，要明确写出来，不能编一个听起来合理的答案。
- **会生成路上方便查的结果**：不仅有完整攻略，也有当天速查、入口与换乘图、当地名称、地址、话术和应急信息。
- **可以按你自己的习惯修改**：长期原则、默认偏好和单次条件分开，避免把一句随口偏好变成永久死规则。

## 三步开始使用

### 第一步：安装或导入

本项目采用标准 `SKILL.md` 结构，同时为不支持原生 Skill 的 AI 提供文件上传方式。

| AI / Agent | 推荐使用方式 |
|---|---|
| OpenAI Codex | 链接到 `~/.codex/skills/plan-reliable-trips`，然后使用 `$plan-reliable-trips` |
| TRAE | 在 SOLO 模式导入 GitHub Skill，或放入项目的 `.trae/skills/plan-reliable-trips` |
| WorkBuddy | 下载 Release 中的技能压缩包，在技能页面选择“添加技能 → 上传技能” |
| Claude Code | 放入 `~/.claude/skills/plan-reliable-trips` 或项目 `.claude/skills/` |
| Cursor | 放入项目 `.cursor/skills/` / `.agents/skills/`，也可以从 GitHub 导入 |
| Windsurf | 放入工作区 `.windsurf/skills/` 或全局 Skills 目录 |
| GitHub Copilot | 放入项目 `.github/skills/` / `.agents/skills/` 或个人 Skills 目录 |
| Gemini CLI | 使用 `gemini skills link` 链接本项目中的技能目录 |
| 其他支持文件的 AI | 上传核心规则、单次出行表和本次需要的专项规则 |

每个平台的准确目录、界面步骤、调用方法和限制见 [各 Agent 安装与使用指南](docs/agent-platforms.md)。平台功能会更新，该文档会标注核验日期并链接官方说明。

不支持原生 Skill 时，可以从 [Releases](https://github.com/Lukala23/ai-travel-planning-kit/releases/latest) 下载 `ai-travel-planning-kit-portable.md`，把这一个文件上传给 AI；它由模块化规则自动生成，方便使用，但长期修改仍建议回到仓库源文件。

Codex 的快速安装示例：

```bash
git clone https://github.com/Lukala23/ai-travel-planning-kit.git
cd ai-travel-planning-kit
mkdir -p ~/.codex/skills
ln -s "$PWD/skill/plan-reliable-trips" ~/.codex/skills/plan-reliable-trips
```

### 第二步：告诉 AI 这次出行的信息

不需要每次填写一张又长又固定的表。最低限度通常只需要：

- 目的地与旅行边界；
- 完整日期和可用时长；
- 人数、同行者及重要限制；
- 出发点、结束点和已经订好的项目；
- 大致预算或成本敏感度；
- 这次最想得到的体验。

其他信息可以写“未知”。详细字段见 [单次出行表](skill/plan-reliable-trips/assets/trip-brief-template.md)。

跨平台通用的第一次指令：

```text
请使用 AI 旅行规划工具包处理这次出行。

目的地：……
日期：……
人数与同行者：……
预算：……
已经预订：……
最想获得的体验：……
其他限制：……

请先把这些信息整理成本次任务卡。只追问会明显改变安全、
可行性、住宿区域、交通骨架、总预算或核心体验的问题。
先给我候选研究和关键取舍，不要立刻生成一份看似完整的逐时攻略。
```

### 第三步：确认关键选择，再生成正式攻略

建议先和 AI 确认：

1. 真正值得去的核心地点与被排除的营销型地点；
2. 住在哪个区域，以及是否有值得专门换住的体验型住宿；
3. 城市和天数怎样分配，主要交通怎样衔接；
4. 哪些预约、支付、签证、天气或安全条件会改变行程；
5. 当前预算下应该保留什么、删减什么。

确认后再说：

```text
关键选择已经确认。请生成完整旅行方案和执行方案。
把住宿、每日路线、交通、用餐、预算、预约、支付、摄影建议、
风险与备选放进同一套计划，并生成适合手机查看的速查版。
所有动态信息标出查证日期和需要再次复查的时间。
```

## 最终会拿到什么

需要完整交付时，AI 应从同一份权威内容生成：

| 文件 | 什么时候用 |
|---|---|
| `00_开始这里.md` | 看版本、最近核验时间、文件目录和使用方法 |
| `01_出行速查卡.pdf` | 在路上快速看当天时间线、地址、入口、支付、返回和紧急信息 |
| `02_完整旅行手册.md` | 继续修改、版本管理，或交给另一个 AI 继续处理 |
| `02_完整旅行手册.pdf` | 手机搜索、离线阅读、分享，或只上传一个文件给 AI 问答 |
| `media/` | 摄影参考图、难找入口、换乘定位图和必要示意图 |
| `03_打印应急版.pdf` | 国外、偏远、徒步或通信不稳定时按需携带 |

短途或简单旅行不必机械生成所有文件；需要什么就交付什么。

## 怎样让 AI 的信息更可靠

工具包会要求 AI：

- 对价格、开放、预约、班次、签证、天气、道路、步道、支付和库存进行本次联网核验；
- 对安全、法律和高价不可退项目使用至少两个独立来源，其中一个来自主管机构或直接运营方；
- 用官方来源确认规则和运营状态，用近期游客信息补充排队、找路和真实现场问题；
- 只把社交平台用于发现候选，不把点赞、排名或高分当成“值得去”的证据；
- 用 `已查证 / 出发前复查 / 取决于条件 / 尚不确定 / 规划判断` 标明结论状态；
- 在来源冲突时保留冲突并解释风险，不编造价格、坐标、班次、票务或所谓官方建议。

任何 AI 都可能出错。工具包可以提高规划的完整度和可复查性，但不能自动保证所有信息正确；重要预订、高风险活动和临近出发的动态信息仍需要最终人工确认。

## 怎样增加或修改自己的偏好

你可以直接和 AI 逐项讨论，不需要先学会写规则。关键是让 AI 先判断你的意见属于哪一类：

| 类型 | 例子 | 处理方式 |
|---|---|---|
| 安全 / 法律底线 | 关闭步道不执行、不建议向公职人员付款 | 固定规则，优先级最高 |
| 长期硬约束 | 无障碍要求、明确不能使用的交通方式 | 写入长期规则 |
| 默认偏好 | 普通观光默认采用正常游客可承受的节奏 | 没有特别说明时采用，本次可以覆盖 |
| 软偏好 | 喜欢有趣、便携、有本地特色的小礼物 | 只作为加分项，不变成严格门槛 |
| 单次参数 | 这次的目的地、人数、预算、是否度假 | 只放进本次任务卡，下次重新提供 |

推荐提示词：

```text
请只审阅【住宿 / 摄影 / 饮食 / 交通 / 其他主题】相关规则。
先复述当前规则会怎样影响实际行程，再判断我的意见属于长期规则、
默认偏好、软偏好还是本次参数。不要把我的随口倾向扩写成僵硬要求。
提出简化后的修改文本，等我确认后再改文件。
```

完整方法见 [与 AI 一起审阅和修改偏好](docs/ai-review-guide.md)。

## 推荐的使用节奏

- **刚开始规划**：确认目的地边界、天数、预算、住宿区域和交通骨架；
- **预订前**：核验签证、许可、热门预约、演出、跨城交通、酒店房型与取消规则；
- **出发前约 7 天**：更新天气、临时关闭、施工、展厅、步道、餐厅和主要路线；
- **出发前约 48 小时**：复查预警、航班 / 列车 / 轮渡、入口、集合点、支付和网络备份；
- **旅行中**：只修改真正受变化影响的后续部分，同时保护重要预约、安全返回和住宿衔接。

时间节点按本次风险选用，不要求每趟旅行机械执行全部步骤。

## 适用边界与隐私

- 本项目用于旅行研究和决策辅助，不替代使领馆、政府、运营方、医生、保险公司、持证向导或现场救援人员；
- 动态信息会变化，安装规则不会自动让没有联网能力的模型获得实时数据；
- 徒步轨迹审核、天气判断和安全建议都不是安全认证；
- 不要把护照号、身份证号、完整银行卡、支付密码、验证码、未脱敏订单二维码或详细家庭地址放进公开仓库或不可信模型；
- 使用者应根据健康、能力、装备、当地法规和现场情况做最终决定。
