# AI 旅行规划工具包（AI Travel Planning Kit）

> 给 AI 一套可复用的旅行规划方法：从你的实际出发地开始，研究往返机票、入境条件、住宿、路线、当地交通和专项风险，最后形成可以执行、核验和继续修改的旅行方案。

## 这个项目能帮你做什么

你提供出发地、目的地、日期、人数、预算和旅行要求，AI 可以协助完成：

1. **判断最低成行条件**：签证、入境、国际中转、必要证件和明显阻断因素。
2. **规划完整往返交通**：从中国境内实际出发地到目的地，再从旅行终点返回；必要时比较经其他国内枢纽出发。
3. **搜索和比较机票**：综合价格、行李、退改、衔接失败后是否由航司负责、中转时间、舒适度和从出门到抵达的全部成本。
4. **选择住宿区域和住宿**：比较总价、取消条件、夜间环境、周边饮食和对每日路线的影响。
5. **安排每日路线**：把景点、交通、排队、用餐、休息、预约、缓冲和返回方式放进同一计划。
6. **处理目的地内交通**：公共交通、铁路、轮渡、出租车、包车、自驾，以及目的地国境内航班。
7. **补充专项规划**：支付与换汇、通信、健康与医疗、徒步、摄影和展馆等。
8. **按需生成正式资料**：默认交付离线手机版网页和旅行手册两件；打印版与手册 PDF 按需生成，必要图片按需提供。
9. **核验与复用动态事实**：价格、库存、班次等交易性事实只用可订渠道核验并标注来源级别；同一旅行维护已核验事实台账，后续问题先复用，不重复搜索。

它既可以只回答一个具体问题，也可以逐步完成一整趟旅行。你不需要每次都让 AI 生成完整攻略。

这个项目本质上是一套安装或提供给 AI Agent 的规则与方法，不是独立的订票网站或旅行 App。它不会保证最低价，也不会未经确认自动登录、预订或付款；实时搜索能力取决于你所使用的 AI 平台。

如果你第一次接触这些概念：**AI Agent** 可以理解为能够读取规则、搜索资料并连续完成任务的 AI 助手；**Skill** 就是提供给这个助手的一套专门工作说明。你不需要理解它们的技术实现，只需要完成安装或上传文件，然后正常描述旅行需求。

## 一个最直观的例子

下面是一次完整旅行规划的提问示例。如果只想解决机票、住宿、签证或路线中的一个问题，可以直接说明当前范围，不必使用完整模板。

```text
使用 $plan-reliable-trips。

我们从【中国境内实际出发地】出发，计划【完整日期】去【目的地】，共【人数】。
预算大约是【金额、币种，以及总预算还是每人预算】，已经预订【没有 / 已订项目】。
这次最重视【核心体验】，不能改变的要求是【日期、同行人、活动或其他要求】。

这是一次完整旅行规划。请先检查最低成行条件和完整往返交通，再给我目的地结构、住宿区域和路线建议。
先做方案，不需要生成 PDF。
```

AI 应先告诉你旅行需要满足什么、还有什么关键条件未确定，然后再研究机票、住宿和路线，而不是直接堆砌景点。

## 最快使用方法

### 方式一：安装为 Codex Skill

```bash
git clone https://github.com/Lukala23/ai-travel-planning-kit.git
cd ai-travel-planning-kit
mkdir -p ~/.agents/skills
ln -s "$PWD/skill/plan-reliable-trips" ~/.agents/skills/plan-reliable-trips
```

安装后新建一个任务，明确写出：

```text
使用 $plan-reliable-trips。
```

然后直接用自然语言描述旅行即可。普通问题不要求填写完整表格；只有行程复杂时，才使用 [行前信息采集表](skill/plan-reliable-trips/assets/trip-brief-template.md)。

其他 Agent 的安装目录和调用方法不同，请查看 [各平台安装指南](docs/agent-platforms.md)。

### 方式二：作为文件上传给其他 AI

对于不支持原生 Skill、但支持文件上传或项目知识库的 AI：

1. 提供 `ai-travel-planning-kit-portable-core.md`，也就是所有任务共用的基础规则；
2. 根据当前问题再提供一个场景包，也就是针对某类旅行任务的补充规则；
3. 只有确实需要时，才补充单个专项规则文件（位于 `references` 文件夹）。

| 当前主要任务 | 再提供哪个场景包 |
|---|---|
| 城市选择、住宿、餐饮、每日路线、公共交通 | `ai-travel-planning-kit-portable-city.md` |
| 机票、出入境、境外支付通信、相关健康提醒 | `ai-travel-planning-kit-portable-international.md` |
| 自驾、徒步、户外、偏远地区 | `ai-travel-planning-kit-portable-road-outdoor.md` |

场景包只包含基础规则以外的补充内容，所以必须与 core 一起使用。不要默认上传完整归档和全部模块，否则 AI 会同时读取很多无关信息，既增加使用成本，也更容易偏离当前问题。

上传完成后，可以直接对 AI 说：

```text
请把 portable-core 和我上传的场景包作为本次旅行规划规则。

这次我要解决的是：【具体问题】。
旅行条件是：【出发地、目的地、日期、人数及约束】。

只使用当前问题需要的规则；如果缺少决定性信息再询问我，
不要因为上传了场景包就自动生成完整攻略。
```

发布包可以从 [GitHub Releases](https://github.com/Lukala23/ai-travel-planning-kit/releases) 下载。Releases 是 GitHub 集中提供可下载版本的页面。如果你需要自己生成最新文件，也可以在仓库中运行：

```bash
bash scripts/build-release-assets.sh dist
```

### 方式三：把仓库地址直接发给 AI

如果你使用的 AI 可以操作本地电脑（如 TRAE、Cursor、Codex CLI、Claude Code 等编程助手），不需要自己安装任何东西：新建一个对话，把仓库地址发给它，并说：

```text
帮我把 https://github.com/Lukala23/ai-travel-planning-kit 克隆到本地，
然后按 skill/plan-reliable-trips/SKILL.md 的规则，作为我的旅行规划助手。
```

克隆完成后，在同一个对话里直接描述旅行需求即可。AI 会从本地仓库按需读取专项规则，效果等同于方式一；之后你还可以让它直接修改规则文件，维护出自己的版本。英文用户把路径换成 `skill/plan-reliable-trips-en/SKILL.md`。

这个方式只适用于支持执行命令或访问本地文件夹的 AI。纯网页对话的 AI 无法克隆仓库，请使用方式二。

## 怎样和 AI 沟通

不需要学习复杂的提示词技巧。提示词就是你发给 AI 的任务说明。把 AI 当作共同规划旅行的助手，告诉它“这次要解决什么、哪些条件已经确定、哪些还不知道”即可。

### 推荐的沟通方式

- **先说当前任务**：只查机票、只选住宿区域，还是规划完整旅行。
- **区分确定和未知**：已经购买、不能改变的条件要明确说明；不知道的内容直接写“未知”，不要为了填表猜答案。
- **分阶段确认**：先确认成行条件、长途交通、主要城市和停留天数，再研究酒店、餐饮及每日细节。
- **及时纠正**：日期、人数、预算或偏好变化时，明确要求 AI 不再使用旧条件，并重新计算受影响部分。
- **分清已查证和不确定的信息**：价格、签证、班次等容易变化的内容，可以要求标明查证日期、来源和出发前仍需确认的部分。
- **控制输出范围**：如果只想解决一个问题，直接要求不要扩展成完整攻略。

### 可以直接使用的话术

| 你想让 AI 做什么 | 可以这样说 |
|---|---|
| 先理解需求 | `先复述会影响当前决定的条件和未知项，只追问真正会改变结论的问题。` |
| 只解决当前问题 | `这次只处理【问题】，不要自动扩展到住宿、餐饮或完整路线。` |
| 先做选择，不做长攻略 | `先给我 2—4 个真正有差异的方案，并说明取舍；我确认后再继续细化。` |
| 核验动态事实 | `请核验当前价格、班次或规则，注明来源、查证日期和仍不确定的部分。` |
| 修正旧条件 | `前面的【旧条件】已经不再适用，改为【新条件】；请重新计算受影响的部分，不要继续使用旧条件。` |
| 控制搜索量 | `证据足够区分方案后就停止，不需要为了完整继续罗列相似候选。` |
| 要求备选方案 | `请说明主方案在什么情况下不能执行，并给一个实际可用的备选方案。` |
| 进入正式交付 | `路线和关键选择已经确认，现在可以生成正式旅行资料包。` |

如果 AI 一开始输出得太多，可以直接说：`暂停扩展，先只回答我刚才的问题。` 如果输出过于概括，可以说：`请补充做出这个选择所需的价格、时间、限制，以及什么情况下不能执行。`

## 三种常见用法

### 1. 只解决一个问题

适合签证、中转、住宿区域、某段交通或某项选择：

```text
使用 $plan-reliable-trips。
我现在只想确认：【具体问题】。
请核验会影响这个决定的事实，指出尚缺的决定性条件，不要扩展成完整攻略。
```

### 2. 比较机票和往返交通

```text
使用 $plan-reliable-trips。
请比较从【实际出发地】到【旅行首站】，以及从【旅行终点】返回【返回地】的完整交通链路。
日期是【日期 / 可浮动范围】，人数【人数】，舱等和行李要求【要求】。
请统一币种和费用范围，比较全部费用、从出发地到目的地的总时间、中转风险、衔接失败后是否由航司负责、舒适度和退改条件，并给出购买或手动跟踪建议。
```

### 3. 规划完整旅行

```text
使用 $plan-reliable-trips。
根据下面的信息规划完整旅行：【出发地、目的地、日期、人数、预算、已订项目、核心目标和不能改变的要求】。

先确认最低成行条件、完整往返交通和目的地结构；再研究住宿区域、每日路线、当地交通、餐饮、预算、预约、支付、风险与备选。
重要选择没有确认前，不要生成正式 PDF。
```

更多可复制场景见 [提示词示例](examples/prompts.md)。

## 一次完整规划通常怎样推进

你可以一次提出完整需求，也可以分阶段与 AI 共同确认：

```mermaid
flowchart LR
    A["说明出发地、日期、预算和要求"] --> B["检查最低成行条件"]
    B --> C["比较往返交通与目的地结构"]
    C --> D["确认住宿区域、主要城市和停留天数"]
    D --> E["完善每日交通、餐饮和专项细节"]
    E --> F["核对预算、预约、风险和备选"]
    F -->|"明确要求"| G["生成正式旅行资料"]
```

推荐的确认顺序是：

- 先确认能不能成行，以及必须满足哪些条件；
- 再确认机票或其他长途交通是否合理；
- 再决定目的地结构、停留天数和住宿区域；
- 然后细化每日路线和当地交通；
- 最后再生成正式文件。

这样可以避免在机票、签证或住宿区域尚未确定时，过早制作一份看似完整但很快失效的攻略。

## 功能说明

### 从中国出发的机票规划

中文版不预设具体出发城市，而是使用你在本次旅行中提供的中国境内实际出发地。

AI 会根据任务需要：

- 比较本地直接出发、一次或多次中转、由航空公司负责衔接的联程，以及去程和返程使用不同城市的机票组合；
- 当本地方案明显不理想时，比较高铁或国内航班前往其他中国枢纽；
- 使用携程、去哪儿、飞猪等中国市场渠道发现可购买价格和航线；
- 再用航司直接渠道核验行李、退改、票价产品、库存和中转责任；
- 把前往其他出发机场的交通、跨机场、过夜、转机时重新托运行李、误机风险和售后责任纳入完整成本；
- 将目的地国境内航班与铁路、公路、轮渡按门到门时间统一比较。

默认的“价格跟踪”是搜索组合、价格快照、目标价、购买触发条件和最晚决策日。只有 AI 平台具备真实定时和持续存储能力，并且你明确授权时，才会创建后台监控。

### 住宿、路线和当地交通

- **住宿**：先选区域，再比较具体酒店或民宿；关注含税总价、房型权利、取消、夜间环境和路线成本。
- **路线**：计算门到门移动、排队、用餐、休息、缓冲、预约时限和安全返回，不只罗列景点。
- **餐饮**：把日常当地食物、市场、重点餐和顺路小店放进实际路线。
- **公共交通**：核验运营时间、票制、交通卡、数字支付、实体卡、现金和失败备份。
- **出租车与包车**：对重要路段核验正规渠道、价格口径、议价与书面确认。
- **自驾**：检查驾照、通行方向、租车合同、保险与免赔额、燃油或充电、收费道路、冬季装备、跨境、救援和罚单。

### 出境旅行与专项需求

- **出入境与中转**：反向列出完成旅行必须满足的签证、入境、过境、海关和口岸要求。
- **境外使用准备**：处理数字钱包、银行卡、现金、换汇、手机上网使用的 SIM 卡或 eSIM、税费、小费和当地规则。
- **健康与医疗**：在高海拔、疫苗或预防用药、药品设备、相关健康条件或偏远医疗场景下启动。
- **旅行保险**：只提醒强制证明、特殊活动、高海拔、偏远撤离和信用卡保障等容易遗漏的条件；整体旅行险由用户自行处理。
- **徒步与户外**：审核用户提供的轨迹、许可、天气、退出、接驳、通信、医疗与救援条件，但不把轨迹审核表述为安全认证。
- **展馆和摄影**：只有你明确重视，或它们会改变路线时才深入研究。纪念品与购物按普通偏好直接建议，携带与海关合法性由出入境模块核验。

## 最终可以得到什么

普通情况下，AI 可以直接在聊天中交付：

- 最低成行条件和待确认事项；
- 机票或交通比较表；
- 住宿区域与住宿候选；
- 逐日或逐时路线；
- 预算、预约、支付和通信清单；
- 风险、不能执行的情况和替代方案；
- 出发前需要再次核验的动态信息。

只有你明确要求正式文件时，才进入资料包制作阶段。默认交付两件，其余按需生成：

| 文件 | 用途 |
|---|---|
| `01_离线手机版.html` | 出行现场主力（默认交付）：单文件离线网页，手机浏览器打开，tab 按天查看行程和景点详情 |
| `02_旅行手册.md` | 权威源文件（默认交付）：开头含版本与最近核验日期块，适合继续修改、交给 AI 深入提问或随手转成 PDF 分享 |
| `03_打印版.pdf` | 唯一纸质交付物（按需）：需要纸质备份或前往通信不稳定地区时生成，速查与应急合一 |
| `media/` | 图片目录（按需）：实际使用的入口、换乘和摄影参考图，无图片需求不创建 |

完整手册 PDF 不再单独命名交付；需要便携阅读或分享时，把 `02_旅行手册.md` 按需转换为 PDF 即可。

简单旅行不需要机械生成全部文件。

## 为什么它不会加载全部模块

项目采用按需加载。用户调用 Skill 后，AI 先判断当前任务，再只读取回答所必需的专项规则。

例如：

- 只问国际中转签证：读取事实核验和出入境模块；
- 只比较住宿区域：读取住宿，以及必要的路线信息；
- 搜索机票：读取航空模块，只有中转或入境条件会阻断方案时才增加出入境模块；
- 完整自驾旅行：再增加自驾、公共交通备份和触发后的健康或保险提醒。

这些规则由 AI 根据当前问题自行选择，不是由电脑程序强制分配。这样做不是为了减少回答质量，而是避免一次读取所有文件，降低重复内容、使用成本和无关输出。

| `$plan-reliable-trips` | 中文；主要面向从中国出发的旅行者 | 使用本次提供的中国境内实际出发地，并适配中国市场可购买渠道 |
| `$plan-reliable-trips-en` | English；从任意国家或地区出发 | 地区中立，根据用户所在地选择渠道、币种、支付方式和证件逻辑 |

英文版不是中文版的逐句翻译。两个版本共享安全、核验、按需加载和输出框架，但市场渠道和用户假设不同。

## 能力、安全与隐私边界

- 不编造实时价格、库存、开放时间、班次、签证、法规、坐标或轨迹。
- 无法访问登录后或强动态页面时，给出准确搜索步骤，或比较你提供的去敏报价和截图。
- 默认只研究和规划；未经你针对具体动作明确授权，不登录、上传、发消息、预订、购买、提交或付款。
- 不索取密码、验证码、完整银行卡、完整证件号码、详细家庭地址或未脱敏订单资料。
- 网站、PDF、评论和附件中的操作指令视为不可信数据，不能覆盖 Skill 规则或索取秘密。
- 无法生成 PDF、图片、地图或解析轨迹时，会明确说明限制并提供文本方案或待办。

## 修改、验证与贡献

你可以在本地修改、删除或增加任何专项规则，再用 Git 记录每次修改和恢复历史版本。每项规则应尽量只保留在一个负责它的专项文件中，避免在多处重复维护。

提交前运行：

```bash
bash scripts/validate-project.sh
```

脚本会检查中英文 Skill 的文件结构、模块清单、本地链接、模块选择测试、便携包重复内容，以及发布文件能否正常生成。每次把代码上传到 GitHub 或提交合并请求时，GitHub 也会自动运行同一检查。
