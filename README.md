> **TravelSpec AI 不是另一个“输入目的地，立刻吐出一张行程表”的旅行生成器。**
>
> 它是一套开源的 AI 旅行规划约束、检索标准、决策流程和交付协议：让大模型知道该查什么、怎样判断、哪些信息必须现查、怎样承认不确定，以及最后怎样交付一份旅行中真正用得上的攻略。

---

## 为什么需要 TravelSpec AI

多数 AI 旅行攻略看起来很完整，却常在真正出发时失效：

- 景点来自热门榜单，热度被误当成价值；
- 营业时间、票价、签证、交通和步道状态已经过期；
- 行程只算景点，不算排队、吃饭、换乘、行李、缓冲和安全返回；
- 住宿只是随手列几个酒店，没有与路线、夜间闲逛、饮食和总成本共同优化；
- 国外交通只写“坐地铁 / 打车”，却不说明手机能否支付、是否需要本地钱包、司机正常价格和常见加价手法；
- 博物馆只写入口和闭馆，没有判断真实馆藏价值、中文讲解和实际馆内动线；
- 摄影建议只写“适合拍照”，没有样片、站位、方向、光照和普通游客能否复现；
- 徒步路线写得很勇敢，却没有可靠轨迹、许可、退出、救援、保险、医疗和通信审查；
- 最终文档很长，但在路上找不到酒店地址、入口、车站、话术和当天真正要做的事。

TravelSpec AI 的目标不是让答案更长，而是让每一个关键结论更可靠、更容易执行和复查。

## 它解决什么问题

| 领域 | TravelSpec AI 的做法 |
|---|---|
| 景点筛选 | 经典与小众同时搜索，剔除营销噪音，不用点赞和排名代替旅行价值 |
| 住宿 | 比较区域与具体住宿，把全程总价、交通、周边闲逛、当地饮食和体验型住宿一起决策 |
| 饮食 | 寻找本地人真实日常选择，不复制网红榜单，并把餐食排进当天路线 |
| 公共交通 | 核验票制、运营商、手机 / 银行卡是否真正可用，以及支付失败备份 |
| 打车与包车 | 给具体路线的价格参考、计价单位、书面确认话术、防骗和求助方案 |
| 出境旅行 | 区分正式收费、税费、服务费、小费、押金与非官方索费，提供运行安全卡 |
| 博物馆 | 判断真实在展价值、中文理解方式、是否值得请中文导游及可执行馆内动线 |
| 摄影 | 为真正值得的点提供参考图、站位、方向、光照、手机构图和可复现性判断 |
| 徒步 | 用户下载轨迹后再审核版本、异常跳点、错误支线、限制路段、关键节点和保障条件 |
| 最终交付 | 同一权威内容源派生完整 Markdown、可搜索 PDF、现场速查卡、图片和按需打印应急版 |

## 最重要的设计：固定约束与单次参数分离

TravelSpec AI 不建立一张永远不变的“旅行者画像”，也不要求每次按固定顺序填写几十个问题。

它只区分两类信息：

1. **固定规划约束**：信息核验、便利度判断、安全底线、候选筛选和交付质量等长期规则；
2. **单次出行参数**：这次去哪、什么时候、几个人、预算、已经订了什么、采用什么交通、体力和特殊目标。

目的地、国内 / 国外、观光 / 度假 / 自驾 / 徒步等标签可以自由叠加。上一次旅行的预算、同行人和路线不会被偷偷带入下一次。

```mermaid
flowchart LR
    A["单次出行信息"] --> B["按本次标签加载相关规则"]
    B --> C["联网研究与候选筛选"]
    C --> D["住宿、饮食、交通与路线共同优化"]
    D --> E["用户审阅关键取舍"]
    E --> F["正式旅行资料包"]
    F --> G["T-7 / T-48 动态复核"]
```

## 十组经过审阅的核心约束

1. 景点搜索、真实价值与营销噪音；
2. 住宿研究、体验型住宿与在地饮食；
3. 公共交通、包车、特殊交通、支付与通信；
4. 出境、通关、税费、小费与国家实际情况；
5. 路线密度、缓冲、天气与可执行备选；
6. 摄影、必拍点、出片时间与参考图片；
7. 国内外徒步、轨迹审核、保险、医疗和保障；
8. 博物馆、中文讲解、纪念品与本地购买；
9. 动态信息核验、来源、状态标记与最终检查；
10. 完整手册、速查卡、图片、PDF、打印与 AI 问答。

完整的逐部分讨论记录在 [约束审阅文档](docs/constraint-review.md) 中。

### 方式一：作为 Codex Skill 使用

OpenAI 官方说明中，放在 `~/.codex/skills` 的技能可跨仓库使用，技能也可以随仓库提交供团队共享。参见 [Save workflows as skills](https://learn.chatgpt.com/codex/use-cases/reusable-codex-skills)。

```bash
git clone https://github.com/Lukala23/travelspec-ai.git
cd travelspec-ai
mkdir -p ~/.codex/skills
ln -s "$PWD/skill/plan-reliable-trips" ~/.codex/skills/plan-reliable-trips
```

如果目标位置已经存在同名技能，请先比较或备份，不要直接覆盖。随后在新的 Codex 任务中调用：

```text
目的地：……
日期：……
人数与同行者：……
预算：……
```

### 方式二：在其他支持文件的 AI 中使用

至少提供：

- [SKILL.md](skill/plan-reliable-trips/SKILL.md)；
- [固定规划原则](skill/plan-reliable-trips/references/planning-principles.md)；
- [信息核验规则](skill/plan-reliable-trips/references/source-verification.md)；

让 AI 先读规则，再根据本次旅行加载相关模块。上下文有限时不要一次塞入全部文件；按任务选择比“全部粘贴”更可靠。不同平台对 Markdown、图片、PDF、联网和工具调用的支持不同，使用效果也会不同。

## 第一次使用，不需要填完整张表

最低限度通常只需要：

- 目的地与旅行边界；
- 完整日期和可用时长；
- 人数、同行者及重要限制；
- 出发点、结束点和已经订好的交通 / 住宿 / 演出；
- 大致预算或成本敏感度；
- 这次是普通观光、度假、自驾、徒步，还是多种方式组合；
- 真正不能妥协的目标。

其余字段可以写“未知”，让 AI 只询问会实质改变方案的缺项。详细字段见 [单次出行表](skill/plan-reliable-trips/assets/trip-brief-template.md)。

## 推荐的五阶段工作流

### 1. 先建立本次任务卡

不要直接说“给我一个七天攻略”后接受第一版。先让 AI 复述：

- 它采用了哪些日期、人数、预算和硬约束；
- 哪些内容尚未确定；
- 哪些只是为了继续规划而采用的临时假设。

### 2. 先做候选研究和关键选择

在生成逐时行程前，先确认：

- 哪些地点是真正的核心体验；
- 住宿应该落在哪个区域；
- 哪些交通、支付、预约或季节条件会改变路线；
- 哪些著名地点因为价值低、营销重、成本高或当前关闭而被排除。

### 3. 再生成路线草案

路线必须计入门到门移动、排队、用餐、休息、缓冲、行李和安全返回。天气、关闭或误点备选必须写清触发条件，不能只是复制另一整套行程。

### 4. 确认后生成正式资料包

默认结构：

| 文件 | 用法 |
|---|---|
| `00_开始这里.md` | 查看版本、最近核验时间和使用说明 |
| `01_出行速查卡.pdf` | 路上快速看当天时间线、地址、入口、支付、返回和紧急信息 |
| `02_完整旅行手册.md` | 权威源文件，适合继续修改和交给 AI |
| `02_完整旅行手册.pdf` | 手机搜索、分享，或只上传一个文件给 AI |
| `media/` | 摄影样片、入口 / 换乘定位图和必要示意图 |
| `03_打印应急版.pdf` | 国外、偏远、徒步或通信不稳时按需生成 |

### 5. 在正确时间更新

- `T-30 天`：签证、许可、热门预约、保险和跨城交通；
- `T-7 天`：开放状态、局地天气、施工、餐厅与路线骨架；
- `T-48 小时`：天气预警、航班 / 列车、步道、接驳和重要预约；
- 行程中：只调整受变化影响的后续节点，并保留返回和备份。

这些时间点按实际风险选用，不要求每趟旅行机械执行全部层级。

## 怎样与 AI 科学地讨论和修改约束

不要把每一句偏好都直接写成永久规则。建议先把意见分成五级：

| 类型 | 例子 | 应该写到哪里 |
|---|---|---|
| 安全 / 法律底线 | 关闭步道不执行、不建议向公职人员付款 | 固定规则，优先级最高 |
| 长期硬约束 | 无障碍需要、明确不能采用的交通 | 固定规则 |
| 默认偏好 | 普通观光采用平衡密度 | 固定规则，但允许本次覆盖 |
| 软偏好 | 喜欢有趣、便携的纪念品 | 只作为加分项，不扩写成僵硬标准 |
| 单次参数 | 这次预算、人数、目的地、是否度假 | 只写入本次任务卡 |

推荐每次只审一个主题，并要求 AI：

1. 先复述它理解的真实意图；
2. 指出这是长期规则、软偏好还是单次参数；
3. 说明会修改哪个文件、影响哪些输出；
4. 给出简化后的规则文本，不扩写无关细节；
5. 修改后重新展示确认项并执行结构校验。

完整方法见 [与 AI 一起审阅和修改约束](docs/ai-review-guide.md)。

## “科学使用”具体指什么

这里的“科学”不是声称旅行规划可以消除不确定性，而是采用可复查的证据纪律：

- 价格、开放、预约、班次、签证、天气、道路、步道、支付和库存必须当次联网核验；
- 安全、法律和昂贵不可退项目至少使用两个独立来源，其中一个来自主管机构或直接运营方；
- 官方来源证明规则和运营状态，游客内容只补充排队、找路和现场体验；
- 社交平台热度只能发现候选，不能独立证明“值得去”；
- 使用 `已查证 / 出发前复查 / 取决于条件 / 尚不确定 / 规划判断` 明示不确定性；
- 来源冲突时保留冲突和风险，不用流畅文案掩盖；
- 不编造价格、坐标、班次、票务、路线和所谓“官方建议”；
- 徒步轨迹审核、天气判断和安全建议都不能写成绝对安全保证。

## 图片不是装饰，而是决策工具

TravelSpec AI 只在图片比文字更有效时使用图片：

- **摄影参考图**：展示值得借鉴的构图、站位、方向和光照，并说明普通游客能否复现；
- **入口 / 换乘定位图**：标出难找的入口、闸口、站台、集合点、上车点或徒步起点；
- 所有图片都应带来源、核验日期和文字替代；
- 重要信息不能只存在于截图或二维码中；
- 无人机、长焦压缩、重度后期、特殊季节和非公开站位必须明确标记。

## 国外旅行的语言设计

地点详情默认提供：

- 中文名；
- 当地官方名称；
- 官方英文名（如有）；
- 可复制到地图的检索名；
- 当地文字地址；
- 入口、出口、站台和柜台的现场原文标识。

还可按场景生成司机目的地与总价确认、拒绝额外项目、索取收费明细、酒店入住、饮食限制和紧急求助话术。未经充分核验的复杂机器翻译必须标出。

## 适用边界与免责声明

- 本项目是旅行研究与决策辅助，不替代使领馆、政府、运营方、医生、保险公司、持证向导或现场救援人员；
- 动态信息会变化，仓库中的规则不会自动让任何模型获得实时数据；
- AI 可能误读来源、地图、图片和轨迹，重要预订与高风险活动必须由使用者最终核对；
- 请勿把护照号、身份证号、完整银行卡、支付密码、验证码或详细家庭地址提交到公开仓库或不可信模型；
- 使用者应根据自身健康、能力、装备、当地法规和实时环境做最终决定。
