# AI 旅行规划工具包：完整使用指南

[English](usage-guide.en.md)

本指南说明怎样使用 **AI 旅行规划工具包（AI Travel Planning Kit）**完成一次真实旅行：从第一次告诉 AI 目的地，到确认住宿和路线，再到生成资料包、临行更新和旅途中查询。

如果你只想先完成安装，请看 [各 Agent 安装与使用指南](agent-platforms.md)。

## 1. 选择使用方式

### 原生 Agent Skill

Codex、TRAE、WorkBuddy、Claude Code、Cursor、Windsurf、GitHub Copilot 和 Gemini CLI 对 Skills 的目录、导入和调用方式各不相同。请根据 [平台指南](agent-platforms.md) 安装，不要把 Codex 的目录直接套用到其他软件。

Codex 示例：

```bash
git clone https://github.com/Lukala23/ai-travel-planning-kit.git
cd ai-travel-planning-kit
mkdir -p ~/.agents/skills
ln -s "$PWD/skill/plan-reliable-trips" ~/.agents/skills/plan-reliable-trips
```

目标位置已经存在时不要直接覆盖。先比较现有版本，或把仓库克隆到其他目录再决定怎样合并。

Codex 调用示例：

```text
使用 $plan-reliable-trips，根据下面的信息规划这次旅行。
只提取当前问题所需的条件；有会改变路线或安全的歧义时再询问我。
```

### 文件上传模式

不支持原生 Skill、但支持文件上传或工作区上下文的 AI 也可以使用。先上传 `ai-travel-planning-kit-portable-core.md`，再按当前任务增加最接近的场景增量包。增量包不重复 core，不能单独替代 core：

| 场景包 | 适用范围 |
|---|---|
| `portable-city.md` | 目的地候选、逐日路线、需要选择的住宿 / 餐饮和公共交通 |
| `portable-international.md` | 航空链路、出境 / 中转、触发后的健康与必要保险提醒 |
| `portable-road-outdoor.md` | 自驾、徒步、健康和相关保障提醒 |

某个专项不在场景包内时，再从 Skill 压缩包增加对应的 `references/*.md`。例如只有用户明确重视摄影、展馆已进入主路线或需要购买纪念品时，才增加相应文件。完整 `ai-travel-planning-kit-portable.md` 只用于归档、兼容或确实需要全库检索的平台，不是默认上传方式。

自然语言通常已经足够，不要求同时上传完整任务卡；只有用户已经填写或行程条件特别复杂时才加入高级模板。

## 2. 准备一次旅行需要的信息

不要把整个人生偏好写入每次任务，也不要为了填表而猜答案。

### 必要信息

- 目的地和旅行边界；
- 出发、结束日期与可用天数；
- 出发点、结束点；
- 人数、同行者及明显限制；
- 已经购买或不可改变的项目；
- 大致预算或成本敏感度；
- 旅行方式和本次最重要目标。

### 只有相关时才填写

- 机票日期弹性、舱等 / 行李、中转与红眼容忍、自行转机、是否接受从本次实际出发地先到其他中国枢纽、机票预算 / 退改和已有价格提醒；
- 自驾证件、通行方向、车型、车辆保障 / 免赔额、燃油 / 充电、收费、停车和跨境需求；
- 非徒步高海拔、药品 / 医疗设备、慢性病 / 孕期、疫苗或医疗可达性；
- 已有旅行保险、不可退金额、特殊活动和信用卡保障启用状态；
- 徒步能力、海拔经验、轨迹来源；
- 中文导游预算；
- 摄影强化意愿；
- 送礼人数与纪念品预算；
- 无障碍、儿童、饮食、医疗或特殊活动。

未确定的信息写“未知”。完整表格见 [单次出行表](../skill/plan-reliable-trips/assets/trip-brief-template.md)。

## 3. 分别选择任务范围、核验强度和交付形式

不要把“研究得多不多”“事实要多可靠”和“是否生成文件”绑成一个等级。普通情况下让 AI 分别选择：

- 当前范围：窄问题 / 当前方案 / 综合研究；
- 核验强度：常规 / 高后果；
- 交付形式：聊天 / 结构化计划 / 正式文件。

例如签证或中转问题可以是“窄问题 + 高后果核验 + 聊天回答”，无需同时研究住宿、支付和完整路线。

### 阶段 A：提取必要条件

普通问题不需要先生成完整任务卡。只有条件复杂或存在关键歧义时，让 AI 简要复述会影响决定的参数：

```text
先不要扩展成完整路线。请只整理当前决定需要的已知事实、
硬约束、尚未确定和临时假设，不要打印无关专项字段。
只追问会改变安全、可行性、住宿区域、交通骨架或总预算的问题。
```

检查 AI 是否错误继承旧旅行的人数、预算、日期、设备或兴趣。复杂任务仍可主动使用可选高级任务卡。

### 阶段 B：最低成行条件核对

需要可执行路线或成行判断时，让 AI 先反向说明本次最低必须满足什么：旅行证件对应的入境 / 许可要求、实际出发地到首个节点及返程的长途交通、预算中的主要刚性成本，以及用户自己提出的前提。涉及未订机票时这里只轻量确认有可售链路和大致完整成本，随后再由航空模块深入比较。用 `已满足 / 待确认 / 不满足` 标出当前状态，再给 `可行 / 条件可行 / 明显不匹配 / 尚无法判断`。条件型方案即使没有发现明显阻断，也要提醒仍需满足和临行复核的条件；纯灵感探索不必运行这一流程。

### 阶段 C：候选与结构

让 AI 先回答：

- 目的地的真正核心体验是什么；
- 哪些知名地点值得去，哪些只是营销声量高；
- 住宿区域怎样影响每日交通、夜间闲逛和饮食；
- 交通、支付、预约、签证、季节和天气有哪些结构性限制；
- 有哪些高成本或高风险决定必须先确认。

这一步的目标是做选择，不是把所有候选塞进路线。

### 阶段 D：路线草案

路线至少应包含：

- 每日开始和结束；
- 门到门移动、排队和缓冲；
- 正常用餐和休息；
- 重要预约的最晚时间；
- 返回住宿或下一交通节点的方案；
- 天气、关闭和误点时可执行的删改；
- 费用单位与必要 / 可选区分。

### 阶段 E：专题核验

按本次情况检查：

- 从中国境内实际出发地开始的完整往返 / 开口程机票：携程、去哪儿、飞猪等用户可购买渠道的同口径价格，航司直接渠道的库存、行李、退改与联程责任，以及经其他中国枢纽的前置交通、住宿和自行转机风险；不能访问动态价格时改给搜索步骤或比较用户截图；购票或跟踪协议要有触发条件和最晚决策日；
- 住宿总价、税费、取消和精确房型；
- 公交是否真正支持用户现有钱包 / 卡；
- 打车、包车和特殊交通的正常价格及书面话术；
- 当地 SIM / eSIM、漫游和离线备份；
- 自驾合同、CDW / LDW 与免赔额、燃油 / 充电、收费标签、冬季装备、跨境、救援、罚单和取还车证据；
- 出境旅行只做必要保险提醒：强制证明、特殊活动 / 海拔、偏远撤离或用户计划依赖信用卡保障；整体旅行险和完整条款由用户自行处理；
- 触发健康模块时的疫苗 / 预防用药、药品跨境、非徒步高海拔、食水媒介、医疗点与撤离；
- 法定税、服务费、小费、押金与非官方索费；
- 博物馆真实在展内容、中文支持和中文导游价值；
- 摄影参考图、站位与普通游客可复现性；
- 徒步轨迹、许可、退出、救援、保险和医疗。

### 阶段 F：正式交付

路线和关键选择确认后再要求：

```text
路线已经确认。请生成正式旅行资料包。
使用同一 Markdown 权威源派生离线手机版、完整 PDF、速查卡和必要图片；
所有文件写明版本、生成日期、最近核验日期和复查节点。
```

正式资料包中，`01_离线手机版.html` 是出行现场的主力交付物：单个离线网页文件，出发前保存到手机，用手机浏览器直接打开，无需联网。它用 tab 导航切换总览、按天行程和景点等视图，按天时间线中的景点可点击跳转详情，正文可搜索。`01_出行速查卡.pdf` 是它的打印对应物，在需要纸质备份或没有浏览器的场景按需生成，不是每次交付的固定负担。

## 4. 怎样判断信息是否可靠

### 来源分工

| 来源 | 适合证明什么 | 不能单独证明什么 |
|---|---|---|
| 政府 / 主管机构 | 法律、签证、许可、安全、正式费用 | 主观体验 |
| 景点 / 运营方 | 开放、票务、班次、入口、政策 | “最值得” |
| 中国机票平台 + 航司直接渠道 | 当次中国市场路线 / 价格，以及库存、行李、退改和联程责任 | 未来一定涨跌或提醒后仍有库存 |
| 预订平台 | 当次库存、渠道总价、取消条件 | 长期稳定质量 |
| 专业机构 / 研究资料 | 馆藏、历史、文化与专业判断 | 当前开放状态 |
| 地图与近期游客 | 找路、排队、施工、现场感受 | 法律、安全和正式规则 |
| 社交平台 | 发现候选、观察普通照片 | 真实价值和当前合法状态 |

### 五种状态

- `已查证`：当前直接来源明确支持；
- `出发前复查`：当前可用，但临近出发可能变化；
- `取决于条件`：取决于天气、许可、交通或用户决定；
- `尚不确定`：来源冲突、过期或无法访问；
- `规划判断`：由多个事实推导出的建议，不是来源原话。

要求 AI 把引用放在结论附近，并注明查证日期。安全、法律和昂贵不可退项目至少使用一个主管机构或直接运营方；原文含糊、冲突、无法访问，或错误后果严重且实际可行时，再增加第二个独立来源。

## 5. 摄影图片与入口截图

摄影参考图应该回答“我能借鉴什么”，而不是堆漂亮图片：

- 站在哪里、朝哪个方向；
- 什么时间和光照更好；
- 人物放在哪里；
- 手机广角还是标准视角更适合；
- 是否依赖无人机、长焦压缩、重后期或特殊季节。

入口 / 换乘图片应该回答“现场怎样认出来”：

- 正确门、闸口、出口、站台或集合点；
- 图上圆圈和箭头；
- 当地文字的入口名称；
- 可复制地图名称 / 地址；
- 附近地标和查证日期。

关键指引必须另有文字版，不能只留在截图中。

## 6. 徒步轨迹审核

用户先在自己的徒步软件中取得可靠路线，再提供：

- 路线链接或编号；
- GPX、KML、FIT 等轨迹文件；
- 软件截图；
- 关键路径点清单。

AI 应检查来源与版本、起终点、距离爬升、断裂跳点、错误支线、关闭 / 限制路段，以及山屋、水源、检查站、危险段、退出和接驳。结论使用：

- `可用`；
- `条件可用`；
- `不建议使用`。

轨迹文件审核不是安全认证。现场天气、许可、能力、装备和救援条件仍可能使路线不可执行。

## 7. 出发前更新

### T-30 天附近

- 签证、许可、保险；
- 热门预约、演出和跨城交通；
- 住宿取消节点；
- 需要较早准备的向导或特殊活动。

### T-7 天附近

- 进入较可靠预报窗口后的局地天气；
- 临时关闭、施工、展厅与步道状态；
- 餐厅、班次和主要路线；
- 行李、衣物和装备调整。

### T-48 小时附近

- 天气预警和山地 / 海岸局地条件；
- 航班、列车、轮渡和接驳；
- 重要预约、入口和集合点；
- 当天支付、网络与离线备份。

## 8. 旅行中怎样使用资料包

- 现场以 `01_离线手机版.html` 为主：手机浏览器打开，用 tab 按天查看行程，点击时间线中的景点跳转详情，正文可直接搜索；
- 需要纸质备份或没有浏览器时，使用速查卡 PDF（离线手机版的打印对应物）；
- 需要完整背景、图片和备选细节时，在完整 PDF 中搜索地点中文名、当地名、`[入口]`、`[支付]`、`[风险]`、`[拍摄]` 等标签；
- 把完整 PDF 发给 AI 时，要求它指出引用章节和文件核验日期；
- 询问实时变化时，要求 AI 联网复核，不要只依据旧资料包；
- 临时删改后检查后续预约、交通、用餐、返回和住宿是否连锁变化。

可复制提问：

```text
这是截至某个日期的旅行手册。请先告诉我它的核验日期。
回答时指出使用的章节；涉及今天的天气、开放、票价、班次和道路状态时，
请重新联网核验，并明确区分“手册原文、当前更新、你的新判断”。
```

## 9. 隐私与安全

任务卡只写规划所需条件，不写：

- 护照号、身份证号；
- 完整银行卡、支付密码和验证码；
- 不必要的手机号、账号凭据；
- 详细家庭地址；
- 未脱敏的订单二维码和证件照片。

公开提问或提交 Issue 前，再检查行程日期、住宿订单、联系人和定位信息是否需要脱敏。

## 10. 发现规则不合适时

不要因为一次旅行中的随口倾向就修改整个工具包。使用 [AI 审阅指南](ai-review-guide.md)，先判断它是：

- 固定安全底线；
- 本次硬约束；
- 可覆盖默认；
- 软偏好；
- 单次参数。

个人条件和本次偏好留在任务卡；只有明确要改变工具包行为时，才修改负责该主题的专项文件，并记录影响范围。不建立单独的长期偏好索引。
