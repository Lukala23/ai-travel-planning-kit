# TravelSpec AI 使用指南

本指南说明怎样把 TravelSpec AI 用于一次真实旅行，而不是只让 AI 生成一篇看起来像攻略的文章。

## 1. 选择使用方式

### Codex Skill

把 `skill/plan-reliable-trips` 放入或链接到 `~/.codex/skills/plan-reliable-trips`。OpenAI 官方的 [Save workflows as skills](https://learn.chatgpt.com/codex/use-cases/reusable-codex-skills) 说明，`~/.codex/skills` 中的技能可跨仓库使用。

```bash
git clone https://github.com/Lukala23/travelspec-ai.git
cd travelspec-ai
mkdir -p ~/.codex/skills
ln -s "$PWD/skill/plan-reliable-trips" ~/.codex/skills/plan-reliable-trips
```

目标位置已经存在时不要直接覆盖。先比较现有版本，或把仓库克隆到其他目录再决定怎样合并。

调用示例：

```text
使用 $plan-reliable-trips，根据下面的信息规划这次旅行。
先整理单次任务卡，再告诉我还缺哪些会改变路线或安全的关键信息。
```

### 其他 AI

其他支持文件上传、联网检索和图片理解的 AI 也可以使用这套规则。建议先给它：

1. `SKILL.md`；
2. `planning-principles.md`；
3. `source-verification.md`；
4. `output-contract.md`；
5. 本次任务卡；
6. 本次相关的专项规则。

模型上下文有限时，按本次任务加载文件：

| 本次任务 | 加载文件 |
|---|---|
| 过夜旅行 / 选酒店 | `accommodation.md` |
| 路线跨越正餐 | `dining.md` |
| 公交、地铁、铁路、轮渡 | `public-transit.md` |
| 打车、接送、包车、马车等 | `taxi-charter.md` |
| 自驾 | `self-drive.md` |
| 国外 / 跨境 | `international-travel.md` |
| 徒步 / 登山 | `hiking-rules.md` |
| 博物馆 / 展馆 | `museum-visits.md` |
| 摄影与出片 | `photography.md` |
| 正式 PDF / 速查卡 | `deliverable-package.md` |

## 2. 准备一次旅行需要的信息

不要把整个人生偏好写入每次任务，也不要为了填表而猜答案。

### 必要信息

- 目的地和旅行边界；
- 出发、结束日期与可用天数；
- 出发点、结束点；
- 人数、同行者及明显限制；
- 已经购买或不可改变的项目；
- 大致预算或成本敏感度；
- 旅行方式和本次最重要目标。

### 只有相关时才填写

- 自驾证件、车型、停车需求；
- 徒步能力、海拔经验、轨迹来源；
- 中文导游预算；
- 摄影强化意愿；
- 送礼人数与纪念品预算；
- 无障碍、儿童、饮食、医疗或特殊活动。

未确定的信息写“未知”。完整表格见 [单次出行表](../skill/plan-reliable-trips/assets/trip-brief-template.md)。

## 3. 正确的规划顺序

### 阶段 A：任务卡

让 AI 先复述它采用的参数：

```text
先不要排路线。请把我的信息整理成单次任务卡，分成：
已知事实、硬约束、软偏好、尚未确定、临时假设。
只追问会改变安全、可行性、住宿区域、交通骨架或总预算的问题。
```

检查 AI 是否错误继承旧旅行的人数、预算、日期、设备或兴趣。

### 阶段 B：候选与结构

让 AI 先回答：

- 目的地的真正核心体验是什么；
- 哪些知名地点值得去，哪些只是营销声量高；
- 住宿区域怎样影响每日交通、夜间闲逛和饮食；
- 交通、支付、预约、签证、季节和天气有哪些结构性限制；
- 有哪些高成本或高风险决定必须先确认。

这一步的目标是做选择，不是把所有候选塞进路线。

### 阶段 C：路线草案

路线至少应包含：

- 每日开始和结束；
- 门到门移动、排队和缓冲；
- 正常用餐和休息；
- 重要预约的最晚时间；
- 返回住宿或下一交通节点的方案；
- 天气、关闭和误点时可执行的删改；
- 费用单位与必要 / 可选区分。

### 阶段 D：专题核验

按本次情况检查：

- 住宿总价、税费、取消和精确房型；
- 公交是否真正支持用户现有钱包 / 卡；
- 打车、包车和特殊交通的正常价格及书面话术；
- 当地 SIM / eSIM、漫游和离线备份；
- 法定税、服务费、小费、押金与非官方索费；
- 博物馆真实在展内容、中文支持和中文导游价值；
- 摄影参考图、站位与普通游客可复现性；
- 徒步轨迹、许可、退出、救援、保险和医疗。

### 阶段 E：正式交付

路线和关键选择确认后再要求：

```text
路线已经确认。请生成正式旅行资料包。
使用同一 Markdown 权威源派生完整 PDF、速查卡和必要图片；
所有文件写明版本、生成日期、最近核验日期和复查节点。
```

## 4. 怎样判断信息是否可靠

### 来源分工

| 来源 | 适合证明什么 | 不能单独证明什么 |
|---|---|---|
| 政府 / 主管机构 | 法律、签证、许可、安全、正式费用 | 主观体验 |
| 景点 / 运营方 | 开放、票务、班次、入口、政策 | “最值得” |
| 预订平台 | 当次库存、渠道总价、取消条件 | 长期稳定质量 |
| 专业机构 / 研究资料 | 馆藏、历史、文化与专业判断 | 当前开放状态 |
| 地图与近期游客 | 找路、排队、施工、现场感受 | 法律、安全和正式规则 |
| 社交平台 | 发现候选、观察普通照片 | 真实价值和当前合法状态 |

### 五种状态

- `已查证`：当前直接来源明确支持；
- `出发前复查`：当前可用，但临近出发可能变化；
- `取决于条件`：取决于天气、许可、交通或用户决定；
- `尚不确定`：来源冲突、过期或无法访问；
- `规划判断`：由多个事实推导出的建议，不是来源原话。

要求 AI 把引用放在结论附近，并注明查证日期。安全、法律和昂贵不可退项目至少两个独立来源，其中一个应是主管机构或直接运营方。

## 5. 摄影图片与入口截图

摄影参考图应该回答“我能借鉴什么”，而不是堆漂亮图片：

- 站在哪里、朝哪个方向；
- 什么时间和光照更好；
- 人物放在哪里；
- 手机广角还是标准视角更适合；
- 是否依赖无人机、长焦压缩、重后期或特殊季节。

入口 / 换乘图片应该回答“现场怎样认出来”：

- 正确门、闸口、出口、站台或集合点；
- 图上圆圈和箭头；
- 当地文字的入口名称；
- 可复制地图名称 / 地址；
- 附近地标和查证日期。

关键指引必须另有文字版，不能只留在截图中。

## 6. 徒步轨迹审核

用户先在自己的徒步软件中取得可靠路线，再提供：

- 路线链接或编号；
- GPX、KML、FIT 等轨迹文件；
- 软件截图；
- 关键路径点清单。

AI 应检查来源与版本、起终点、距离爬升、断裂跳点、错误支线、关闭 / 限制路段，以及山屋、水源、检查站、危险段、退出和接驳。结论使用：

- `可用`；
- `条件可用`；
- `不建议使用`。

轨迹文件审核不是安全认证。现场天气、许可、能力、装备和救援条件仍可能使路线不可执行。

## 7. 出发前更新

### T-30 天附近

- 签证、许可、保险；
- 热门预约、演出和跨城交通；
- 住宿取消节点；
- 需要较早准备的向导或特殊活动。

### T-7 天附近

- 进入较可靠预报窗口后的局地天气；
- 临时关闭、施工、展厅与步道状态；
- 餐厅、班次和主要路线；
- 行李、衣物和装备调整。

### T-48 小时附近

- 天气预警和山地 / 海岸局地条件；
- 航班、列车、轮渡和接驳；
- 重要预约、入口和集合点；
- 当天支付、网络与离线备份。

## 8. 旅行中怎样使用资料包

- 先看速查卡获得当天立即行动信息；
- 在完整 PDF 中搜索地点中文名、当地名、`[入口]`、`[支付]`、`[风险]`、`[拍摄]` 等标签；
- 把完整 PDF 发给 AI 时，要求它指出引用章节和文件核验日期；
- 询问实时变化时，要求 AI 联网复核，不要只依据旧 PDF；
- 临时删改后检查后续预约、交通、用餐、返回和住宿是否连锁变化。

可复制提问：

```text
这是截至某个日期的旅行手册。请先告诉我它的核验日期。
回答时指出使用的章节；涉及今天的天气、开放、票价、班次和道路状态时，
请重新联网核验，并明确区分“手册原文、当前更新、你的新判断”。
```

## 9. 隐私与安全

任务卡只写规划所需条件，不写：

- 护照号、身份证号；
- 完整银行卡、支付密码和验证码；
- 不必要的手机号、账号凭据；
- 详细家庭地址；
- 未脱敏的订单二维码和证件照片。

公开提问或提交 Issue 前，再检查行程日期、住宿订单、联系人和定位信息是否需要脱敏。

## 10. 发现规则不合适时

不要直接在一次旅行中悄悄覆盖长期规则。使用 [AI 审阅指南](ai-review-guide.md)，先判断它是：

- 固定安全底线；
- 长期硬约束；
- 默认偏好；
- 软偏好；
- 单次参数。

然后只修改真正需要修改的文件，并记录影响范围。
