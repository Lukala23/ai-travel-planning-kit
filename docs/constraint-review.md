## 2026-08-14 新增专项：航空交通、机票搜索与购票时机

- 从用户本次提供的中国境内实际出发地规划完整去程和返程；先比较直出、一次中转和受保护联程，只有明显值得时再考虑先到其他中国枢纽，不固定假设某几个城市一定更好。
- 中国出发的路线、日期和价格发现优先检查当次可访问的携程、去哪儿、飞猪等中国市场渠道，尽量交叉两个可购买渠道；最终候选再由航司直接渠道核验库存、行李、票价产品、退改和中转责任。国际搜索工具只补充灵活日期、附近机场和境外航段。
- 经国内枢纽的方案必须加入前置航班 / 高铁、跨机场、住宿、两段行李、自行转机、误机和体力成本；不能用更低的国际段票面价直接证明完整行程更便宜。
- 候选按完整含税价格、必要附加项、门到门时间、舒适度、行李、联程保护、退改与售后统一比较，只保留真正不同的综合推荐、最低完整成本和更舒适 / 低风险方案。
- 购票时机不给统一“提前 20 天 / 100 天”答案。按本次航线现价、可辨认的低价日历 / 趋势、连续价格快照、日期刚性、节假日和替代航班，给 `建议现在购买 / 设置价格提醒观察 / 等待条件明确 / 尚无法判断`。观察方案必须有目标完整价格、买入条件和最晚决策日期；提醒触发后仍需复价。
- 平台无法访问或没有可靠路线级历史数据时，明确保留不确定性并给精确搜索组合，不编造价格趋势。未经明确授权不下单、登录、兑换积分或填写旅客和支付信息。

本专项已按中文版“从中国实际出发地开始”确认；英文版采用地区中立的航司、当地 / 区域渠道和用户销售市场逻辑，不逐句复制中国市场假设。

## 第 1 部分：景点搜索与价值筛选

### 已确认规则

- 先确定目的地边界：本城、本区域、周边一日往返分别是什么。
- 同时搜索经典、小众、季节限定、需预约和与本次目标匹配的地点。
- 内部尽可能广泛地搜索，最终只向用户展示筛选、去重和分级后的结果。
- 不把网红榜单、平台排名、评分、点赞或打卡人数当作旅行价值证据。
- 国外地点同时使用官方英文名、当地语言名和地图可检索名搜索。
- 去除同名、景区子项目和重复包装的体验。
- 每个候选用容易理解的维度评价：为什么值得去、为什么适合这次旅行、去起来是否麻烦、什么时间合适、需要付出什么、计划失败时怎么办。
- “为什么适合这次旅行”必须具体对应本次的目标、天数、同行人、预算、节奏、交通或硬限制；资料不足时直接写“尚不能判断”。
- “信息确认情况”只说明信息是否已经查清，不参与景点价值排名；用户侧简化为 `已查证 / 出发前复查 / 尚不确定`，仅在会影响选择时显示。
- 摄影不是唯一固定价值，也不是每个候选的必填项。排线时作为加分项轻量扫描；确有价值才展开角度、光线、方式和沿途拍摄机会。
- 某地点同时具有重大摄影价值和独立判断后的重大社交发图价值，而且新增的时间、费用、体力、安全、拥挤与同行者成本可控时，提高路线优先级，给予合适时段和足够停留；社交发图价值看地方辨识度、画面叙事和真实可复现性，不看平台热度。
- 知名不等于必须去，小众也不等于值得去。

### 营销噪音甄别

- 社交平台和榜单只用于发现候选，再用近期普通游客原图、详细文字、负面反馈、地图尺度和现场运营信息交叉核验。
- 检查相似营销文案、同一机位 / 滤镜、赞助或返现关系、短期集中高分、只展示无人机 / 长焦 / 重修图画面等信号。
- 比较真实可体验内容、合理停留时间、排队、门票、绕行和附加消费是否相称。
- 跨平台内容必须真正独立；转载同一营销素材不算多个证据。
- 只能根据可观察信号标记“营销风险高”，证据不足时不得指控刷分或造假。

### 已确认的分级

- `A 核心体验`：高度适合本次旅行、难以替代，值得围绕它排线。
- `B 高质量推荐`：值得去，但可按时间和地理取舍。
- `C 有条件可选`：顺路、天气合适、有余力或有特定兴趣时加入。
- `D 不建议纳入`：营销声量高于实际价值、成本明显不值、当前条件不成立，或已有显著更好的替代。

D 级只列知名、营销风险高或用户可能疑惑为什么没安排的地点，不输出全部淘汰项。

### 确认结果

- 第 1 部分已确认。后续若要改变本模块的默认或软偏好，可以单独修订；单次个人倾向留在任务卡。

## 第 2 部分：住宿研究、体验住宿与在地饮食

住宿和饮食都属于路线本身。只要需要过夜，模型必须主动研究并推荐住宿方案；只要路线跨越正餐，就必须安排可执行的当地饮食体验，而不是在攻略末尾附两个随意榜单。

### 住宿主动研究与推荐

- 先根据景点、交通和城市结构比较真正有意义的住宿区域，再主动寻找具体住宿，并用住宿结果重算路线。
- 实际搜索根据目的地使用住宿官网、Trip.com（携程国际站）/ 携程、Booking.com、Agoda、Expedia、Hotels.com、Google Hotels / Maps 及当地有效平台；最终候选尽量核对两个可预订渠道和官方渠道。
- 跨平台必须统一日期、人数、房型、床型、景观、早餐、取消、税费和币种；会员 / App 专享价只有用户确有资格时才计入。
- 推荐区域时同时考虑：景点与预约的每日交通、机场 / 车站衔接、市中心闲逛、住宿周边可逛性、夜间返回、当地餐饮、街道步行体验、噪声、安全和生活便利。
- 使用全程真实总成本：房费、税费、清洁 / 服务 / 度假费、早餐、押金、汇率、付款手续费和位置产生的额外交通费。
- 不按单个平台排序或综合评分推荐；核对近期不同房型评价、普通住客照片、反复负面问题和真实入口。
- 最终给明确的综合推荐，并按实际差异提供更省钱、交通更好、城市生活更好或风险更低的替代；数量由目的地复杂度决定，不固定凑长名单。
- 已订住宿只核验适配性及对路线、饮食和预算的影响，除非存在重大问题或用户要求，不无故替换。

### 体验型住宿与换住判断

- 把住宿分为功能型基点和体验型住宿。独特景观、建筑、温泉、历史、在地生活、摄影或社交发布价值都可以让住宿本身成为正式体验节点。
- 默认减少没有收益的搬迁，但“少换住宿”不是最高优先级。体验价值、路线衔接、摄影或体力收益足以覆盖价差、收拾、退房、行李移动、等待入住和天气失败风险时，可以主动推荐换住一晚或多住宿基点。
- 对日照金山等景观住宿，核验具体房型、朝向、楼层、遮挡、公共 / 私人观景位置、日期光线、天气依赖和宣传图片是否真实可复现；不能只看酒店名称或营销图。
- 关键条件未稳定时优先展示可取消价格，同时列出不可退款价差、截止时间和最大损失，由用户决定。

### 在地饮食与每日路线

- 先研究当地人日常饮食、代表菜、小吃、市场和季节性内容，再寻找适合本次路线的具体餐厅、小店或摊位。
- 优先本地客群证据较强、地方性真实、近期出品稳定且价格合理的选择；高级餐厅不是默认优先，街边小店可以同等推荐。
- 小红书和短视频只用于发现线索；Google Maps 相对有用但也会受游客结构、营销和评分偏差影响，必须结合当地语言评价、当地点评 / 预订平台、当前菜单、本地来源和近期普通顾客照片核验。
- 不凭宣传文案写“当地人最爱”。检查当地语言评价、长期经营、所在社区、菜单与本地价格、工作日客流线索和多来源长期提及，只能据此写“本地客群证据较强”等可解释结论。
- 早餐结合住宿周边或当天第一站；午餐结合上午与下午区域；晚餐结合最后节点、夜间闲逛和安全回住宿。将到店、排队、点餐和用餐计入时间。
- 高价值或必须预约的一餐可以成为路线锚点；普通餐次不为打卡跨城折返。重要节点提供同区域主选与备选，其他餐次可给餐饮区域和现场选择规则。
- 核验招牌菜、人均、税 / 服务费、营业、预约、支付、饮食限制与食品安全线索；不因环境普通排除好店，也不因适合拍照忽略味道和价值。

### 确认结果

- 已确认：住宿必须主动搜索、比较并形成明确推荐，不只是被动规则。
- 已确认：住宿区要同时考虑景点交通、市中心及周边闲逛、饮食和真实总成本。
- 已确认：默认减少无收益换住，但体验型住宿具有足够价值时可以主动换住。
- 已确认：关键条件不稳定时优先展示可取消方案，并列不可退款价差。
- 已确认：饮食是旅行体验的一部分，偏好真正本地化、当地客群证据较强的餐厅与小店，不以社交平台热度决定。

第 2 部分已确认。住宿和饮食以后作为路线的核心研究任务执行。

## 第 3 部分：公共交通、包车、特殊交通、支付与通信

这一部分把五件不同的事分开处理：交通是否方便、交通票 / 交通卡、支付与换汇、手机上网，以及出租车 / 网约车 / 包车的价格与安全。你使用什么手机、去哪个国家、乘什么交通，仍由每次行前信息采集表提供。

### 1. 便利度判断

- 不笼统写“交通方便”。按本次住宿和路线计算门到门时间、步行、换乘、班次、首末班、入口 / 出口、行李、寄存、无障碍、夜间返回和错过后的代价。
- 票制、施工、停运和换乘规则核验到具体运营商、线路和票种；车程短不代表整段移动方便。

### 2. 票、通票和交通卡

- 根据本次实际乘车段和人数比较单程票、直接刷银行卡 / 手机、日票 / 通票、游客卡和匿名交通卡，不因名称叫“通票”就判断更划算。
- 购买交通卡前核验购卡地点、卡费 / 押金、初始金额、充值、余额查询、退款、有效期、遗留余额和一人一卡规则。
- 若直接刷现有手机或银行卡同样享受换乘优惠 / 票价封顶，就不为了形式额外买卡。
- 游客 / 匿名交通卡在确实省钱或明显更方便、且不要求本地实名账户时可以购买；这与 SIM / eSIM 手机上网卡是两件事。

### 3. 支付、实体备份和换汇

- 现金、实体银行卡和数字钱包都是正常候选。默认先核验已经配置、可跨地区复用的支付宝、微信支付、Apple Pay、Google Wallet / Google Pay 等数字钱包或手机非接触方式，再与实体卡和现金按本次受理、费用、可靠性和失败后果并列比较；这是一项可覆盖的便利倾向，不是固定阶梯。
- 实体卡或现金在关键场景更可靠、更便宜或覆盖更好时，可以直接作为主方案。目的地专用钱包 / App 只有在关键场景特别实用，或没有它会明显不便、损失价格优惠或无法使用重要服务，且收益足以抵消注册、实名、本地号码、绑卡 / 充值、语言、退款和余额退出成本时才建议。
- 核验到用户手机与绑定方式、具体受理场景、费用、限额、联网和退款，不因出现支付宝、Google Wallet、Visa 等标志就保证可用。
- 可以提前准备实体银行卡和现金，但先计算真实现金场景和数量，再比较国内换汇、合法兑换点和 ATM 的汇率价差、固定费用、取现费、DCC、限额与剩余现金损失。
- 主支付和备份不能依赖同一手机、同一卡或同一账户；同时说明失电、风控、验证码失败、拒付和余额不足后的动作。

### 4. 国际上网与通信

- 国外旅行把网络视为导航、叫车、购票、翻译、支付和紧急联络的基础条件。
- 按确切手机型号比较中国运营商漫游、手机厂商国际上网 / 虚拟 SIM、旅行 eSIM、当地实体 SIM / eSIM 和随身 Wi-Fi；核验频段、覆盖、限速、热点、本地号码 / 短信、激活与全部费用。
- 本地 SIM 在需要本地号码、覆盖明显更好、停留较长或综合成本更低时采用；同时保存离线地图、住宿地址、票券和紧急联系方式。

### 5. 出租车、网约车、接送与包车

- 对机场接送、跨城、全天包车和其他非固定票价路段，必须写明具体起终点、时段、人数、行李和车型，并给当地货币合理价格区间及人民币约值。
- 价格参考优先来自官方固定价 / 计价标准、叫车平台对具体路线的当前估价、持牌公司书面报价和住宿接送报价；近期游客内容只用于识别加价和骗局。资料不足时不猜价格，改为获取 2–3 份书面报价。
- 说明价格是固定价、计价器估算、App 动态价还是包车报价，并列明是否包含过路、机场、停车、等待、行李、夜间、返空、司机餐宿和小费。
- 现场议价或包车前，用当地语言书面确认：起终点、日期时间、车型、整车总价而非每人价格、包含项、额外收费、付款和取消；攻略直接提供可复制话术。
- 上车前核对官方上车点、车牌、车型、司机和订单，不接受无正当理由取消 App 后私下交易、临时换车或改价；保存订单金额、车牌、客服和目的地离线截图。
- 按具体城市、机场、路线和时段预警假司机、计价器异常、绕路、币种偷换、整车变人头价、虚构费用、平台外加价、拒绝找零和以行李施压等风险，不按国家发展程度简单贴标签。
- 护照、手机、现金、药品和重要电子设备尽量随身。遇到临时加价或扣留行李时不进行肢体争夺，在公开有监控地点联系平台、机场 / 车站安保、酒店、旅游警察或警方；个人安全优先，并保留车牌、订单和索价证据。
- 出发前离线保存本次核验过的求助号码和第二交通方案；不保证平台、警方或退款必然解决问题。

### 6. 马车、骑乘与其他特殊交通体验

- 马车、骆驼 / 骑乘、突突车、三轮车、摩托车出租、传统船只等既可以是交通，也可以是正式体验；同样需要提供价格参考、计价单位和防骗提醒。
- 明确价格按整车 / 整船、每人、每小时、每圈还是单程计算，并确认返程、等候、拍照、喂食、讲解、门票和小费是否另收。
- 用书面话术确认路线、时长、结束地点和总价，防止“免费试坐”、短程临时延长、下车后改成人头价、强制购买照片 / 饲料或到偏僻处再索价。
- 摩托车类核验头盔与载客限制；水上项目核验载客、救生衣、天气 / 水况和夜航；动物类检查高温、过载、受伤、消瘦、跛行、呼吸异常和粗暴驱赶，存在明显问题时不推荐。
- 不因为项目有地方特色就忽略安全、合法性或动物福利；条件不合适时提供更正规运营方或其他体验替代。

### 本轮确认结果

- 当前行为：游客 / 匿名交通卡只在本次路线中确实省钱或明显更方便时购买，不为形式增加支付媒介。
- 当前行为：支付按数字钱包软优先、三类方式并列比较、本地钱包条件采用和独立备份执行；本次任务卡可以覆盖便利倾向。
- 已确认：非固定票价交通必须给具体路线价格参考、包含项、书面议价话术、骗局预警和求助方案。
- 已确认：马车、骑乘、传统船只等特殊交通按路线 / 时长给价格参考，同时核验安全、隐性收费和动物福利。

第 3 部分已确认。后续具体价格、骗局类型、平台和求助方式必须针对当次目的地联网查证。

## 第 4 部分：出境、通关与国家实际情况

这一部分只在出境、跨境或国际中转时启用，并且必须根据旅行证件签发地、完整中转链路、停留时间和旅行目的重新核验，不能把别人的国籍规则或旧攻略套用过来。

### 1. 入境、过境和海关

- 查清签证 / 免签、ETA / 电子许可、入境卡、护照有效期与空白页、停留期限、返程 / 资金 / 住宿证明等本次真实要求。
- 区分联程与非联程、是否需要入境、重新托运、换机场、过境签、最短衔接和保守缓冲；航空公司允许登机不等于边检一定准入。
- 核验海关申报、现金、食品、药品、动植物、摄影器材、无人机、卫星设备和户外装备；只索取判断所需条件，不收集证件号码。
- 高风险或不可逆信息至少使用主管机构与第二个独立来源，并设置临行复核时间。

### 2. 正常通关准备与口岸非官方索费

- 每次默认检查可以提前完成的电子签 / ETA、入境卡、海关申报、在线值机、证件预审，以及适用的官方电子闸机或注册旅客计划。这些属于正常准备，不等于花钱“买通关”。
- 机场 / 航司付费快速通道、礼宾或转机协助不作为每次旅行的必查和必选项。只有你主动询问，或本次确有紧张转机、行动协助等明显需求时才研究。
- 必须区分值机、安检、休息室、行李、机场引导与移民边检 / 海关。商业服务不能被写成保证入境、跳过海关或获得公职人员特殊照顾；主管机关若确有公开服务，也只按官方页面说明。
- 正式签证费、出入境费、落地签费等必须查明主管机构公布的金额、支付渠道和收据要求。
- 若官方旅行提示与多个可信近期来源反复报告某个口岸或流程存在索要“手续费”“小费”“加速费”等非官方款项的风险，必须提前告诉你，并明确它不是正常收费；不能凭一两个帖子给整个国家贴标签。
- 不建议向边检、海关、警察或其他公职人员付款。安全可行时，礼貌询问收费名称与官方依据，要求正式窗口 / 电子渠道和收据，必要时请值班主管；不争吵或肢体对抗，人身与证件安全优先，离开危险场景后再联系旅游警察、口岸运营方或使领馆，并保留合法取得的凭证。

### 3. 酒店、餐厅的小费、税费与附加费

- 对本次会遇到的餐厅、酒店、司机、导游、背夫、行李、门童和礼宾等场景，说明是否存在小费惯例、是否自愿、常见金额 / 比例、支付时机，以及已收服务费后是否还通常另给小费。
- 账单必须分开标记：法定增值税 / 销售税、强制服务费、城市 / 旅游 / 住宿税、度假费、餐位 / 面包 / 饮水费、最低消费、银行卡附加费、平台费和自愿小费，不能统称为“税费”或“小费”。
- 每项说明官方或菜单 / 合同依据、金额或比例、是否强制、是否通常已含标价或预订总价、由谁收取、何时支付和能否取得收据。
- 遇到不明的 5%、10% 或其他附加项时，不能仅凭比例判断它是否合法或是什么费用。先索取逐项账单，询问名称、强制 / 可选属性及菜单、预订条款或法规依据；对照原始价格，必要时请经理或平台客服解释并更正。
- 刷卡前核对终端金额、币种和账单一致；已有服务费时避免无意重复给小费。现场以安全为先，不把直接拒付或冲突设为统一答案；保留账单、订单和付款凭证后，可按当地规则使用消费者主管机构、旅游警察、平台申诉或发卡行争议流程。

### 4. 其他真实运行习惯

- 不只写法律，还研究当地会真实影响行程的行业惯例和近期情况，并把官方规则、普遍惯例和个别旅客经验分开。
- 检查周末、宗教日、午休、节庆、罢工、预约习惯、证件携带、住宿登记、着装、饮酒、公共礼仪、摄影和性别相关规则。
- 押金、议价、现金找零、常见骗局和临时加价必须按本次城市与场景核验，不以邻国经验推断。

### 5. 安全、法律与应急准备

- 结合官方旅行提示和当地主管机构，检查本次路线的治安、边境 / 限制区域、示威、宵禁、诈骗、道路和自然风险；不要用全国标签代替城市和路线判断。
- 核验容易被游客忽视的违法行为，例如药品、拍摄政府 / 军事设施、宗教场所、无人机、酒精、电子设备或公开行为限制。
- 准备当地紧急号码、旅游警察、保险救援、就医入口、使领馆 / 领事保护和证件遗失流程；把可执行内容离线保存。
- 不制造恐慌，也不淡化主管机构警告；风险明显超过本次收益时直接给替代地区、路线或日期条件。

### 6. 交付方式

每次国外旅行固定附一张简洁的“国外旅行运行与安全提示卡”，只列本次行程相关的入境 / 口岸、可信来源反复报告的非官方索费、账单与小费、支付 / 换汇、交通骗局、重要法律文化规则、紧急求助和复核时间，不复制百科全书。

收费部分使用：`场景｜费用名称｜常见 / 核验金额｜法定 / 强制 / 可选｜通常是否已含｜建议动作｜来源与核验时间`。没有可靠依据时直接写“尚未查清”，不猜比例。

### 本轮修订结论

1. **已纠正**：付费快速通道不再是每次必须考虑的项目，并与边检 / 海关明确分开。
2. **已增加**：对有可信、普遍证据的口岸非官方索费提前预警，只提供合法、安全的应对，不建议付款。
3. **已增加**：酒店和餐厅的税、强制服务费、其他附加费与自愿小费逐项拆开，并提供不明收费处理步骤。
4. **已保留**：每次国外旅行固定附一张简洁的运行与安全提示卡。

第 4 部分已确认（2026-08-13）。

## 第 5 部分：路线安排、节奏与备选

这部分只约束“路线怎样才真实可执行”。普通观光旅行已有确认的默认方法；度假、高覆盖、每天几点出门和具体体力边界仍可按单次出行调整。

### 1. 先给路线逻辑，再给时间表

- 先说明为什么这样分区、排序和取舍，再写逐时安排；不能用一张看起来精确的表格掩盖不合理路线。
- 不以景点数量最大化为目标，优先保护本次最重要且不可替代的体验。
- 重要但未纳入的候选说明原因：时间不足、重复、绕行、预约冲突、价值不匹配或当前条件不成立。
- 地图时间只是理想估算，不能写成到达保证。

### 2. 时间必须按完整过程计算

总时间包括：

`游览 + 门到门移动 + 候车 / 换乘 + 排队 / 安检 + 寄存 / 找入口 + 用餐 / 休息 + 找路 + 风险缓冲`

- 抵达日先扣除落地 / 到站、提取行李、入境、进城和入住；离开日先保护退房、取行李和前往机场 / 车站的时间。
- 大型博物馆、徒步、摄影等待、特色餐饮和换住宿使用各自的真实时间模型，不能都套普通景点时长。
- 每天必须有真实起点、最终终点和可靠返回住宿 / 枢纽的方案。

### 3. 默认采用平衡观光模式

- 用户很难只通过“松弛 / 平衡 / 紧凑”三个词判断真实强度，因此规划时不能把这道抽象选择题直接交给用户。
- 普通旅游型城市默认采用 `平衡观光模式`：在本次时间、成本、体力、开放和交通允许范围内，尽量覆盖真正有价值的景点，同时保留正常吃饭、休息、完整体验和安全返回，不为堆数量加入低价值地点或过度压缩。
- 用户明确说海边休养、放松或度假时切换为 `度假模式`；明确要求尽可能多游览时切换为 `高覆盖模式`。
- 出发前把拟议模式作为重点确认，但使用具体信息说明：每日预计出发 / 结束时间、核心体验块、总步行与站立、最早 / 最晚硬预约及连续高强度天数，而不是只问一个抽象词。

### 4. 缓冲不设百分比，关键环节必须足够

- 不设固定 10% 或 20%。普通可替换节点保持合理弹性，由模型自行平衡。
- 昂贵演出、定时中文讲解、不可退预约、航班 / 城际车、末班交通、返程日和其他迟到损失很大的环节，按现场不确定性和失败后果留足安全余量，不能只满足理论最短衔接。
- 缓冲必须写进真实时间表，不能最后用一句“请提前出发”代替。

### 5. 季节与临近天气参与排线

- 初步规划先检查季节、日照、典型降水 / 高温 / 严寒 / 大风 / 雾、雪季 / 汛期 / 台风季、海况和季节关闭；历史气候只能作为季节判断，不能伪装成预报。
- 进入可靠预报窗口后，使用目的地局地天气和预警更新路线；普通城市活动可在约 `T-7 天`、`T-48 小时`复查，高风险户外、水上和天气快速变化地区按需要在前一晚 / 当天继续复核。
- 明确天气会影响哪些项目，以及何时调整时段、对调日期、改室内项目、缩短或取消；官方关闭或危险预警时不能强行执行原路线。

### 6. 把路线分成不同稳定程度

- `硬锚点`：已订交通、定时票、中文讲解、演出、最后入场等，不能随意移动。
- `核心体验`：这次最值得保护的内容；延误时优先保留，但可根据开放和体力微调。
- `可移动节点`：可以换时段、换同区域替代或缩短。
- `有余力再加`：只有提前完成、体力和交通条件允许时才进入，不提前承诺一定完成。

延误时按这个层级删减，不通过压缩用餐、休息、转场或安全返回来“完成表格”。

### 7. 备选必须能在现场执行

- 不为每一天机械复制“下雨版、低体力版、晚出发版”三套完整行程；默认不生成晚出发方案，只处理本次真正存在且影响较大的季节、天气、体力、关闭或误点风险。
- 备选写成“触发条件 → 先删 / 改哪个节点 → 替代内容 → 新交通与时间 → 是否影响预约和返回”，不能只列一个备用景点名称。
- 每天指出最先可删除或缩短的节点；硬预约、天气敏感项目和关键交通失败时，再给完整替代方案。
- 多日行程中，可交换日期的项目必须说明交换条件，不能假设门票、营业和交通会自动兼容。

### 8. 参数改变后整体重算

- 日期、住宿、交通、同行者、预算或核心目标变化后，从路线骨架重新计算，不在旧时间表上局部挪动造成连锁矛盾。
- 已确认预订仍作为硬约束；若新条件使其不可行，明确说明冲突与取消代价，不假装兼容。

### 确认结果

1. 普通观光旅行默认平衡观光模式，并在出发前通过具体日程强度确认；度假或高覆盖由本次明确要求切换。
2. 缓冲不设百分比；重要、昂贵、不可退、返程和关键交通环节必须留足安全余量。
3. 季节、日照与近期预报参与路线设计，并为重大天气影响设置可执行调整条件。
4. 默认交付“主路线 + 每日优先删减点 + 真实相关的关键备选”，不默认制作晚出发或三套完整版本。

第 5 部分已确认（2026-08-13）。

## 第 6 部分：摄影、必拍点与出片时间

摄影只改变“哪些地点值得为画面调整时段、站位和停留”，不会把整趟旅行自动变成摄影团。

### 1. 未说明设备时从手机和便携设备开始，不追求器材

- 任务卡没有设备信息时，以手机、最多增加 Osmo Pocket 等随身便携设备作为可覆盖起点，不无必要反复询问相机、镜头或三脚架；本次明确提供的器材和目标优先。
- 拍摄建议以构图、站位、光线、人物位置、画面层次和背景清理为核心，而不是用专业器材弥补审美与观察。
- 只有本次明确携带其他设备或有特殊题材时，才补充器材设置。

### 2. 所有路线扫描，常规景点也给实用拍法

- 安排行程时进行轻量摄影机会扫描；摄影是加分项，不是唯一固定价值或最高权重。
- 不能只研究所谓“摄影圣地”。正式路线中的核心景点和大众常去地点，只要存在可复现的好构图，也要告诉用户在哪里站、朝哪里拍、横竖构图、人物放在哪里、保留什么和避开什么。
- 旅行价值高但摄影表现普通时，可以标为 `记录即可` 并给稳妥纪念照方法，不硬造大片机位。
- 使用 `必拍 / 值得拍 / 记录即可 / 不建议专程拍`；全程扫描，但只有“必拍”和重要“值得拍”制作完整点位卡，避免摄影信息淹没攻略。

### 3. 摄影价值与社交发布价值独立判断

- 不按网红热度、点赞或打卡人数判断；检查当地辨识度、空间层次、光线依赖、合法站位、绕行和等待成本。
- 社交发布价值看画面的地点辨识度、视觉记忆、组图叙事和普通游客能否真实复现，不把热门平台模板当作价值。
- 同时具备重大摄影与社交发布价值，且新增时间、费用、体力、安全、拥挤和同行者成本不复杂时，提高路线优先级；成本明显时给普通游览与拍摄强化两个方案。

### 4. 重点点位必须能真正执行

- 对必拍点给出：准确公开点位、主体、站位朝向、前景 / 构图、人物位置、日期对应光线、手机拍法、等待时间、限制和坏天气备选。
- 使用官方图、地图 / 卫星图、太阳路径和多个近期实景来源独立判断。
- 网络照片若依赖无人机、长焦压缩、重度修图或非公开机位，必须说明。
- 把真正吃光线的点作为路线锚点，其他景点围绕它安排。
- 景点之间、桥上、街区、步道和交通途中有价值的拍摄点，也作为正式节点写入。
- 日出前、蓝调后或偏远机位必须有交通和安全返回方案。
- 不为凑数量虚构机位；没有真正必拍点时直接写“无须专程拍”。

### 5. 参考图片是正式交付内容

- “必拍”和重要“值得拍”默认附 1–3 张实际可见的参考图片；常规知名景点若文字不足以解释构图，也至少附一张代表性参考图或紧凑图片组。
- 每张图片同时给原始来源、作者 / 机构（可获得时）、查证日期和“应该借鉴什么”，例如站位、前景、人物比例或光线。
- 无人机、长焦压缩、重度后期、特殊季节、封路清场或非公开位置必须标明，不能把不可复现的网络画面包装成现场承诺。
- 参考图片用于理解构图，不保证届时天气、云量、花期、倒影、人流和颜色完全相同。

### 6. 早起可以，明显额外成本则单列方案

- 地点真正值得，且睡眠、交通、天气和安全可合理处理时，可以把早起安排进主路线，并写清起床 / 出发时间及当日体力影响。
- 顺路、短等待且费用可控的高价值机会直接整合。
- 长时间等待、明显绕行或需要牺牲其他核心体验时，不自动纳入，只并列提供 `普通游览方案` 与 `拍摄强化方案`。

### 确认结果

1. 未说明设备时从手机 / Osmo Pocket 等便携设备开始，构图与审美优先；这不是长期用户画像，本次器材和目标可以直接覆盖。
2. 真正值得的早起可接受；长等待、明显绕行或牺牲核心体验时，只给拍摄强化选项。
3. 全程扫描、重点展开；常规景点也给出片建议，重点拍法附实际参考图片而不是只有文字。

## 第 7 部分：徒步、国外徒步与路径数据

徒步不能只给一条轨迹和几个景点。必须同时回答：这条路线是否适合本次人员、数据是否可靠、怎样导航、什么时候折返、出了问题如何退出。

### 1. 先匹配真实能力与本次条件

- 先过安全闸门：开放、许可、天气、地形风险、日照、交通、能力和装备。
- 结合本次同行者中能力最弱者，参考近期完成路线、舒适距离 / 爬升、技术地形、恐高 / 伤病、海拔经历、导航能力和已有装备。
- 信息不足时可以先比较候选，但不能把路线写成已经适合；只追问会改变安全、许可或核心路线的条件。

### 2. 路线数据和难度不能猜

- 距离、爬升、海拔、耗时、坐标和 GPX 必须有可靠数据来源，不能猜。
- 难度拆成体能、技术、暴露、环境和失败后果，不只写简单 / 中等 / 困难。
- 给出绿 / 黄 / 红风险，并说明理由。
- 分清单程、往返、环线、穿越和是否含接驳；海拔高度与累计爬升不能混写。

### 3. 路径数据、用户软件、退出与折返

- 用户会在自己的徒步软件中下载并管理路线，不需要模型默认制作打印地图、GPX 文件或逐路口导航。
- 可靠路线 / 轨迹数据是安全门槛：必须核验用户能够取得对应路线，并确认路线名称 / 编号、起终点、版本、更新时间，以及每日住宿、关键岔口、垭口、可靠水源 / 补给、检查站、退出、接驳和危险段等路径点。
- 用户没有可靠轨迹或路径点数据时，默认不执行该路线；不能为了补齐攻略手工猜测或生成轨迹。
- 官方地图 / GPX 优先，再用持证当地机构、可靠地图和近期轨迹交叉验证。
- 单个游客轨迹不能单独证明开放、合法或安全。
- 用户出发前在自己的软件中完成离线下载并确认关键路径点可见；根据路线风险准备电力、第二设备、官方纸图、指北针或合法卫星通信等适当备份，但不机械要求全部携带。
- 不提供未经核验的捷径、越界、私人土地或已关闭路线。
- 用户选好并下载路线后，可以把路线链接 / 编号、轨迹文件、截图或关键路径点清单发给模型审核。审核来源与版本、距离爬升、起终点、轨迹断裂 / 跳点、错误支线、关闭 / 限制路段、山屋水源、退出和接驳，并给出 `可用 / 条件可用 / 不建议使用`；这不是绝对安全认证。
- 给个人折返时间和触发条件：天气恶化、路线不明、进度落后、任何成员出现预设不适或错过接驳风险时执行，不以“快到了”为理由继续。
- 穿越、涉水、海岸、高山和依赖接驳的路线必须有对应失败退出方案。

### 4. 国外徒步的规划重点

- 国外徒步攻略不把主要篇幅用于复述路线转向，而是重点解决进出交通、行李与接驳、许可、天气机动、安全、保险、医疗、住宿、饮食饮水、通信、电力、现金和装备。
- 向导 / 注册旅行社是否强制，国家公园、限制区、TIMS 类许可和检查站；
- 每日最高点与睡眠海拔、上升速度、适应日和必须下降的条件；
- 保险是否覆盖具体活动、最高海拔、直升机 / 地面救援、预授权和垫付；
- 最近可用医疗点、能处理相关情况的医疗机构、转运难度、旅行医学准备、药品 / 医疗设备入境与航空限制；
- SIM / eSIM、离线地图、充电、停电、卫星通信和当地救援流程；
- 山屋 / 茶屋 / 营地的营业、预约、供暖、被褥、食物、饮水和卫生；
- 最后 ATM / 换汇 / 刷卡点、之后需要的现金与支付失败备份；
- 向导和背夫的资质、保险、负重、费用、小费和劳动保障；
- 季风、降雪、山火、雪崩、垭口、山区航班 / 吉普取消和天气机动日；
- 垃圾、露营、火源、野生动物、宗教文化和装备航空运输限制。

不能把国内步道的信息完整度、救援方式、移动支付和住宿条件套到国外。尼泊尔等目的地的许可、TIMS 类规则、向导要求和保险条件必须每次重新核验。

### 5. 向导和背夫由本次条件决定

- 法律强制时必须使用符合要求的持证向导或注册机构；非强制时不因为“国外”自动建议或排除。
- 比较自助、向导、向导 + 背夫在路线熟悉、语言、许可办理、住宿协调、负重、天气判断、急救通信和救援联络上的真实增益，结合本次能力与风险让用户选择。
- 按确切路线、日期、人数、天数和服务方式核验费用，给当地货币与人民币约值。
- 分开列许可、国家公园费、交通、住宿、餐食、向导 / 背夫工资、保险、装备、税费、平台费和小费；说明按人、按团还是按天，哪些已含。
- 比较注册资质、语言能力、带队范围、通信 / 急救、取消、救援责任、背夫负重和劳动保障，不以社交粉丝或最低价决定。
- 无公开价时取得多份同条件书面报价，不编造“当地一般价格”。

### 6. 国外徒步交付方式

- 交付一张“国外徒步执行卡”，依次说明：路径数据是否就绪、进出交通、许可、向导 / 背夫选择、保险与救援、医疗 / 海拔、住宿恢复、食物饮水、通信电力、现金支付、装备和天气 / 放弃条件。
- 路线过程只概括与日程、安全和折返有关的结构；除非用户主动要求核验已有轨迹，否则不生成地图、GPX 或详细导航。

### 确认结果

1. 用户在自己的软件中下载和管理轨迹；不需要打印地图、模型生成 GPX 或逐路口导航。
2. 可靠路线 / 轨迹与关键路径点是安全门槛；没有可靠数据时不建议执行。用户下载后发送给模型做二次审核是默认推荐流程。
3. 国外徒步重点研究出行、安全、保险、救援、医疗、住宿、饮食饮水、通信、电力、现金、装备和天气机动。
4. 向导 / 背夫除法律强制外由本次条件和用户评估决定；模型提供背景、风险、价格、包含项和机构比较。

第 7 部分已确认（2026-08-13）。

## 第 8 部分：博物馆、展馆、纪念馆、纪念品与本地购买

这一部分已经拆成两个不同权重的模块：博物馆 / 展馆规划是可以决定整趟旅行结构的核心内容；纪念品建议是相关场景下的购买辅助，不能用后者弱化前者。

### 1. 展馆可以成为核心旅行锚点

- 所有目的地先轻量扫描值得关注的博物馆、展馆、纪念馆、遗址馆和专业小馆；国家 / 地区首府、知名城市与历史文化城市提高搜索强度。发现真正重要且适合本次的馆就拉入正式候选，不能因为当地并非传统“博物馆城市”或馆的规模较小而忽略。
- 博物馆体系构成目的地核心价值时，即使你没有逐馆点名，也要主动分配合理天数并与住宿、交通、餐饮共同排线；只有单个高价值小馆时，也可作为半日、数小时或顺路核心节点纳入。
- 搜索国家级综合馆、艺术馆、考古 / 历史馆、专题馆、纪念馆、遗址博物馆、名人故居、大学馆、高质量临展和真正有价值的小馆。
- 展馆不默认只是雨天备选，也不默认所有著名大馆都必须去；按 `核心锚点 / 重要补充 / 条件候选 / 不建议纳入` 判断。

### 2. 判断名气背后的真实参观价值

- 分开评价机构名气、建筑知名度、收藏总量和本次真正公开展出的内容，不能用其中一个替代其余三个。
- 检查代表展品是否当前在展、是否真品或复制 / 复原、核心展区是否开放，以及宣传内容是否需要另票或根本无法进入。
- 比较馆藏不可替代性、展陈与叙事质量、与本次兴趣的匹配、和其他馆的重复度、语言门槛、排队、门票、体力与总时间。
- 名气大但展陈弱、核心区域关闭、语言障碍严重或与其他馆高度重复时，说明具体依据后降级；不空泛地说“没意思”。
- 使用当地语言、博物馆协会、大学 / 研究机构、专业文化资料和当地展览信息寻找高价值小馆；不为了“小众”而推荐。

### 3. 中文理解是正式规划条件

- 已记录长期条件：你以中文为母语，英语理解能力有限。重点馆必须主动核验中文展签、纸质地图、语音导览、App、字幕、定时中文团和私人中文讲解，不能因为官网有中文就推断馆内有中文。
- 官方中文支持不足时，攻略要准备简洁中文辅助：入馆前背景主线、重点展区 / 展品、中外文名称、馆内定位、为什么重要、现场看什么细节和易混淆术语。
- 可使用离线翻译作为补充，但不能把机器翻译当成艺术史、考古、年代或专有名词的可靠解释。

### 4. 是否请中文导游必须给明确建议

- 比较官方中文人工讲解、官方中文语音 / App、合法持证中文私人导游，以及“中文行前导读 + 自助参观”。
- 馆藏背景复杂、展厅庞大、中文信息少、本次高度重视，或多人分摊后成本合理时，提高请中文导游的推荐度；官方中文导览已经充分或导游增益不值价格时，不机械建议请。
- 最终必须写清：`建议请中文导游 / 官方中文语音足够 / 建议行前导读后自助 / 取决于预算或兴趣`，并解释理由。
- 价格按本次日期、人数、馆名、语言与时长核验，区分按人 / 按团 / 按小时，给当地货币与人民币约值；门票、导游费、语言附加、耳机、税费、平台费和小费分别列明。
- 核验导游资质、集合点、讲解范围、是否陪同入馆、谁购买门票、取消和迟到规则。私人导游不自动等于“免排队”；无法取得可靠公开价时不猜，改为提供询价渠道和书面询价内容。

### 5. 不只告诉你怎么进去，还要告诉你怎么逛

- 根据馆的规模与本次兴趣提供真正有差异的精华版和深度版；小馆不机械拆版本，大馆不假装能够完整逛完。
- 馆内路线按入口、楼层、展区连接、单向通行、电梯 / 楼梯、拥堵和出口设计，减少折返，优先保护不可替代或可能提前关闭的展区。
- 重点展区 / 展品写明中文名、当地可检索名、馆内位置、为什么值得看、现场观察细节、建议停留和中文理解方式。
- 把安检、寄存、领取导览、找路、排队、休息、卫生间、餐饮、摄影和馆店计入真实总时长；同一天多馆还要考虑站立与信息疲劳。
- 核心展品临时不展、展厅关闭、到馆晚或体力不足时，提供可直接执行的缩短路线。

### 6. 入场、现场与整条路线

- 继续核验入口、实名 / 预约、常设展 / 临展 / 分馆票、闭馆、最后入场、安检、寄存、再入场、无障碍、摄影和展品轮换；这些是基础，不是展馆规划的全部。
- 重点馆可以成为半日或整日锚点，围绕预约、中文讲解和闭馆时间安排交通、用餐、周边街区和回住宿。
- 博物馆密集型目的地先决定真正值得给展馆多少天，再做馆与馆的取舍，不能把每个大馆都压缩成一小时打卡。

### 7. 纪念品与本地购买

- 这是轻量的购买辅助，不是一套收藏或工艺审查制度。默认寻找有当地辨识度、有趣、便携、价格不过高的小物；冰箱贴、明信片、文具、馆藏衍生、小型织物或合规的包装食品都可以。
- 分成“自己留作纪念”和“带给朋友的小礼物”两类，并按当地实际消费给出 `低价多人伴手礼 / 中档有质感小物 / 少量特别款`，同时标当地货币与人民币约值。
- 比较馆店、创作者店、市场 / 书店 / 设计店、超市和机场渠道，说明哪里更有当地特点、哪里价格合适、哪里顺路；不把贵重收藏品设为默认选择。
- 偏手工、少见、不易复制只是加分项，不是硬门槛。普通冰箱贴等低价小物只需判断设计、地方性、价格和携带便利，不讨论没有决策意义的机器辅助或生产细节。
- 保留必要的易碎、保质期、食品检疫、海关和受保护材料提醒；价格较高，或明确声称手工、限量、古董、特定产地时，再深入核验来源和真伪。

### 已记录的长期倾向

- 重点展馆需要真实价值筛选、中文理解方案、是否请中文导游的明确结论、讲解价格与具体馆内游览建议。
- 所有目的地先轻量扫描；首府、知名 / 历史文化城市重点搜索。同步寻找著名大馆和高价值小馆，剔除只有名气或营销声量、但本次实际参观收益弱的地点。
- 纪念品以当地辨识度、有趣、便携和价格合适为主，也包括适合送朋友的低价小礼物；偏手工、少见、不易复制只是软偏好，不默认推荐贵重物品。

### 确认结果

1. 博物馆与展馆采用完整规划：所有目的地轻量扫描，首府和知名 / 历史文化城市加强搜索；真实价值、中文理解、导游价格和具体馆内游览均为正式内容。
2. 纪念品相关表述只作为软偏好，不能把一句随口想法扩写成严格的材质、工艺或生产方式标准。
3. 默认推荐有意思、方便携带、价格合适的自用小物和送朋友礼物，并按目的地给出不同价位；不默认推荐昂贵收藏品。

## 第 9 部分：信息核验、攻略内容与最终检查

这一部分决定最终攻略怎样写、哪些事实必须现查，以及你如何一眼看出哪些内容已经可靠、哪些仍需临行复查。

### 1. 默认交付一份可直接使用的主攻略

- 不再让你先抽象选择“标准版 / 深度版”。默认先给结论和关键取舍，再给可执行路线、住宿、饮食、交通与支付、费用、预约、摄影建议、风险和备选。
- 只输出本次真正相关的模块，不为了看起来完整而塞入无关章节。
- 对安全、法律、高成本不可退项目、复杂展馆或国外徒步等内容自动展开；普通、低风险内容保持简洁。你明确要求深挖时再增加专题附录。
- 规划所依据的日期、人数、预算、已订项目和关键假设放在开头，缺失信息写成未知或条件，不自行编造。

### 2. 动态事实当次查，关键结论就近给来源

- 开放、价格、预约、交通、签证、道路 / 步道、天气、支付、住宿库存、餐厅状态和汇率等动态信息必须在每次规划时重新联网核验。
- 安全、法律和昂贵不可退项目至少使用两个相互独立来源，其中一个应为主管机构或直接运营方；游客内容只用于现场体验和发现待查问题。
- 影响决策的动态结论在对应文字或表格附近放直接来源和查证日期，避免读者到文末猜链接支持哪一句。
- 文末只保留一张简短的关键证据表，不用大量无关链接制造可靠感。

### 3. 用直白状态说明“不确定到什么程度”

- 统一使用 `已查证 / 出发前复查 / 取决于条件 / 尚不确定 / 规划判断`。
- 这些标签只说明信息可靠性与是否会变化，不是景点价值评级。
- 来源冲突时写明冲突、适用日期和风险；无法核验时宁可保留未知，也不写成确定事实。

### 4. 临行清单按任务和时间节点生成

- 已经进入可执行行程时，根据真实需要使用 `现在 / T-30 天 / T-7 天 / T-48 小时 / 当天` 等节点；只列本次适用的预订、支付、网络、保险、交通、天气、证件和安全事项。
- 仍在探索目的地或只比较一个问题时，不机械附“一页清单”。
- 会导致无法入场、误机、无支付方式、步道风险或重大损失的事项优先出现，并标明由谁、何时复查。

### 5. 交付前做一次隐性的完整检查

- 检查日期与星期、时区、费用币种和计价单位、住宿总价、税费 / 服务费 / 小费、支付备份、预约与最后入场、每日返回、关键缓冲、天气备选和重要交通。
- 按本次内容继续检查餐饮、摄影、展馆中文理解、议价交通防骗、国外安全卡、徒步轨迹审核和纪念品携带等专项规则。
- 检查用于模型内部纠错；正文只呈现仍需你处理的事项，不把冗长的自检过程全部输出。

### 本轮建议确认 3 项

1. **默认格式**：不要求你预选“标准 / 深度”，默认交付结论先行、能直接执行的主攻略；仅对复杂或高风险部分自动加深。
2. **来源呈现**：关键动态结论旁放直接来源与查证日期，末尾再附一张精简证据表；同时用五种直白状态标明是否仍需复查。
3. **临行清单**：只有形成可执行行程时才按相关时间节点生成，不在每次探索或简单问答里机械附上。

## 第 10 部分：正式资料包、图片、速查与使用方式

这部分回答“最终到底交付什么、怎样快速找到、怎样在手机 / 纸面 / AI 中使用”。建议采用一个权威内容源派生多种使用视图，而不是维护几套可能互相矛盾的攻略。

### 1. 建议的默认交付包

| 文件 | 主要用途 |
|---|---|
| `00_开始这里.md` | 看版本、最近核验日期、每个文件怎么用以及怎样要求更新 |
| `01_出行速查卡.pdf` | 旅行现场在手机上快速看当天时间线、地址、入口、预订、支付、返回和紧急信息 |
| `02_完整旅行手册.md` | 权威源文件，最适合继续修改、复核或交给支持 Markdown 的 AI |
| `02_完整旅行手册.pdf` | 手机阅读、搜索、分享、普通打印，或只丢一个文件给 AI 提问 |
| `media/` | 手册实际使用的摄影样片、入口 / 换乘截图和必要示意图 |

需要保存整套资料时可以再提供 ZIP。单独离线 HTML 不默认生成；只有你明确希望手机交互搜索 / 折叠导航且确认使用方式时再做，避免文件越做越多。

### 2. 完整手册怎样保持清晰

- 使用可点击目录、PDF 书签和固定标签；开头先放一页旅行总览和“现在需要做什么”。
- 主体按天排列，每天先有一屏 / 一页概览，再展开地点、入口、交通 / 支付、用餐、拍摄、预约 / 风险、返回与备选。
- 住宿、交通、美食、展馆、摄影、国外安全和徒步等专题只在本次相关时出现。
- 文末放双语地点 / 话术索引、关键证据和出发前复查项。信息不在多个章节反复复制，改用内部链接和清晰引用。
- 每个文件显示旅行日期、版本号、生成日期与最近核验日期；更新时先修改 Markdown，再同步重建 PDF 和速查卡。

### 3. 图片怎么用，避免长成“截图堆”

- `摄影参考图`：必拍点和文字很难说明构图的常规景点通常放 1–3 张实际参考图，注明来源、借鉴什么、站位 / 朝向、光照与可复现限制。
- `入口 / 换乘定位图`：只用于真正难找的入口、闸口、站台、集合点、上车点、停车入口、博物馆分馆或徒步起点。用圆圈 / 箭头标出，并同时给地图链接、可复制地址、附近地标和现场标识文字。
- 所有关键内容必须同时有文字版和图片说明，不能让“从哪里进”“看哪个牌子”等信息只藏在截图里。
- 截图注明核验日期；入口、施工和标识可能变化时列入临行复查。来源不清或不能稳定使用的图片不硬塞入 PDF。

### 4. 英语、当地文字与现场标识

- 国外地点使用 `中文名｜当地官方名｜官方英文名（如有）`，另给地图可复制名称和当地文字地址。
- 入口、出口、楼层、站台和柜台保留现场真正出现的原文标识，不只做中文意译。
- 按本次场景准备少量可直接展示的双语 / 当地语言话术：司机目的地与总价、拒绝额外项目、索取收费明细、酒店入住、饮食限制、紧急求助等。
- 机器辅助翻译但没有充分核验的复杂句子必须标出；不依赖中文谐音辨认地点。

### 5. 速查卡、打印版和交给 AI

- 速查卡按天分屏 / 分页，不强行压成一张纸，也不复制完整背景介绍；它只负责现场立即行动。
- 完整 PDF 必须有可选择文字、标题层级、目录书签、内部链接和图片说明，不能是扫描版。因此可以把这一个 PDF 交给能读 PDF 的 AI 继续问具体问题。
- Markdown 对 AI 修改和精确提取通常更友好；平台支持多个文件时，优先上传 Markdown 与 `media/`，只方便上传一个文件时使用完整 PDF。
- 文件开头提醒 AI：这是截至某个日期的规划快照，回答要指出章节；价格、开放、班次、天气、签证、道路 / 步道等仍需按当前时间重新联网核验。
- 国外、偏远、徒步、通信不稳或你明确需要纸质备份时，再生成 `03_打印应急版.pdf`。它使用较大字号、黑白可辨，只保留关键行程、双语地址、预订、交通支付、紧急求助和退出方案，不默认打印整本攻略。

### 6. 实际使用流程

1. 你先提交本次任务卡或自然语言信息，我生成路线草案供讨论。
2. 路线和重要选择确认后，你说“生成正式旅行资料包”，我再制作上述文件，避免在仍频繁修改时反复排版。
3. 出发前说“按 T-7 天复核并更新资料包”；临行再做一次 T-48 小时的天气、开放、交通与安全重点复核。
4. 旅行中优先看速查卡；需要背景、图片、替代方案或细节时搜索完整 PDF，也可以把完整 PDF 交给 AI 继续问。
5. 行程临时变化时，让 AI 明确区分“原手册内容、当次联网更新、新的规划判断”，并指出修改会影响哪些后续节点。

### 确认结果

1. **默认资料包**：采用 `开始这里 + 速查卡 PDF + 完整手册 MD / PDF + media`；HTML 和 ZIP 只按需提供。
2. **图片原则**：只给真正有帮助的摄影样片和定位图，全部带来源、标注、核验日期及文字替代，不堆无用截图。
3. **AI 使用**：Markdown 是权威内容源；完整 PDF 保证可搜索、可读图且能单独交给 AI，但动态事实仍需联网更新。
4. **打印原则**：不默认打印整本；国外、偏远、徒步、通信不稳或你明确需要时，提供精简的打印应急版。
