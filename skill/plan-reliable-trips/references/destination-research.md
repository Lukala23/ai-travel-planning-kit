# 目的地候选研究与分级

本模块用于新目的地、候选全集或路线设计前的必要扫描。研究深度由单次任务决定，不强制每次单独交付完整清单。

## 1. 确定研究边界

说明行政范围、常用旅行范围、周边一日往返区域，以及本次是否包含它们。避免把同名地点、景区子项目和独立目的地重复计算。

根据本次任务选择性搜索：

- 代表性景点、历史建筑、街区与城市空间；
- 国家级与专题博物馆、艺术馆、考古 / 历史馆、纪念馆、遗址馆、名人故居、大学馆、高价值小馆、临展、演出与文化遗产；
- 公园、观景点、海岸、保护区和步道；
- 当地代表饮食、居民常去餐饮区域、市场、在地生活、购物与夜间体验；
- 季节限定、需预约、小众但高度匹配的地点；
- 交通枢纽、功能型住宿区、体验型住宿和可作为路线锚点的位置。

“穷举”指覆盖对本次决策有现实意义的候选集合，不是罗列地图上的每个商户。

所有目的地至少做一次馆类轻量扫描；国家 / 地区首府、知名城市和历史文化城市扩大搜索到国家级馆、城市博物馆、专题馆、纪念馆、遗址馆、大学馆及高价值小馆。扫描发现真正重要的候选，或目的地核心价值明显依赖馆类内容时，按 `museum-visits.md` 比较实际展出内容、展陈质量、中文理解条件、停留成本与重复度；不能只收录游客榜单中的大馆，也不能把馆类候选统一降为雨天备选。

## 2. 先建立空间和时间结构

- 按区域、交通走廊或入口分组；
- 计算区域之间的门到门移动成本；
- 识别开放、预约、季节、光线和末班交通约束；
- 识别看似相近但被河流、山体、铁路或入口方向隔开的地点；
- 找出可能成为整条路线锚点的固定项目。

## 3. 同时评价价值和便利摩擦

每个候选至少包含：

| 字段 | 要求 |
|---|---|
| 名称 | 中文名（当地可检索名称） |
| 旅行价值 | 一句话说明不可替代性，不写空泛宣传语 |
| 为什么适合这次旅行 | 对应本次目标、天数、同行人、预算、节奏、交通或硬限制；不清楚就明确写不清楚 |
| 区域与可达性 | 从本次路线起点的真实到达方式 |
| 建议时长 | 区间，并说明是否包含排队和内部移动 |
| 时间约束 | 开放、预约、最后入场、季节或光线 |
| 便利摩擦 | 低 / 中 / 高，并解释交通、预约、体力和返回成本 |
| 主要代价 | 门票、绕行、排队、体力或天气风险 |
| 信息确认情况 | `已查证 / 出发前复查 / 尚不确定`；只在动态信息会影响取舍时显示 |
| 摄影提醒 | 仅在确有画面价值时写拍摄机会；不要为每个候选填满 |

需要坐标时从可靠地图获取，不得猜测。历史类地点补充关键年代和真正值得看的细节，不复制百科式长介绍。

## 4. 候选分级

按本次任务适配度而非纯热度分级：

- `A 核心候选`：高度匹配且难以替代，值得围绕它排线；
- `B 推荐候选`：价值高，但可按地理、时间和状态取舍；
- `C 条件候选`：顺路、雨天、夜间或有余力时加入。
- `D 不建议纳入`：营销声量高于实际体验、成本明显不值、当前条件不成立，或已有显著更好的替代。

`D` 不需要罗列所有被淘汰地点。只保留知名度高、营销风险高或用户很可能疑惑“为什么没安排”的项目，并说明剔除理由。没有充分证据时使用“营销风险高”，不得直接声称刷分或造假。

单次信息不足时，分别写“通用价值”和“尚需确认的适配条件”，不要假装了解用户。

## 5. 条件式输出

- 用户要求候选全集：交付研究边界、空间分区、A / B / C 表、必要的 D 级排除说明、便利摩擦、预约与季节、关键取舍。
- 用户直接要求路线：内部使用候选母表，但只输出真正影响取舍的部分。
- 用户天数未知：可以给不同天数的路线骨架，但明确这不是最终日程。
- 最终路线需要覆盖检查时，说明重要候选纳入或放弃的原因。
