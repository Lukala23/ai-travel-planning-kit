# 住宿研究、区域规划与推荐规则

仅在需要选择或推荐住宿、比较住宿区域 / 具体住宿，或已订住宿可能改变路线与成本时读取本文件。任何过夜路线都要先确认住宿状态和住宿基点，但住宿已经确定且没有出现重大适配问题时，不为形式而加载完整研究规则或生成替代榜单。

## 1. 先确认本次住宿任务

- 提取入住 / 退房日期、晚数、人数、房间数、床型、儿童政策、预算口径、住宿类型、已订状态和不可妥协条件。
- 明确本次需要：选择住宿区域、推荐具体住宿、跨平台比价、核验已订住宿，或设计包含体验型住宿的多基点方案。
- 住宿已订时，把它作为路线锚点核验；只有发现重大适配问题或用户要求时才建议更换。
- 日期、人数或房间数未知时，可以比较区域和住宿类型，但不得编造可订状态或真实总价。

## 2. 主动检索住宿区域和具体住宿

先根据目的地空间结构和路线骨架建立住宿区域候选，再在高匹配区域主动搜索具体住宿。实际预订研究应按可访问性选择并交叉检查：

- 住宿官方网站或集团官方渠道，用于房型、设施、政策、会员条件和直订权益；
- Trip.com（携程国际站）、携程等适合用户地区的渠道；
- Booking.com；
- Agoda、Expedia、Hotels.com、Google Hotels / Google Maps，以及目的地真正有覆盖的当地预订平台；
- 民宿、公寓、山屋或特色住宿使用其合法官方渠道、管理机构或可靠专业平台。

平台不是固定必查清单。对最终候选，尽量核对至少两个实际可预订渠道，并在可访问时核对住宿官方渠道；若页面受登录、地区、Cookie、动态定价或反爬限制，明确写“当前无法确认”，不转述搜索摘要当作实时价格。所有价格标注来源级别：`当次渠道页面价`（当次可订渠道、当次口径）或 `背景参考区间`（内容性来源、不可购买）；两类数字不得混排在同一张比较表中，分级规则见 `source-verification.md`。

跨平台比较必须使用相同的：

- 完整入住日期与当地时区；
- 成人、儿童、房间数和入住人数；
- 具体房型、床型、景观 / 楼层、早餐和入住权益；
- 免费取消截止时间、预付 / 到店付和退款条件；
- 税费、服务费、清洁费及显示币种。

会员价、App 专享价、移动端价、信用卡权益或不可公开价格只有用户确实具备资格时才能计入主比较；否则作为条件式节省方案。不同平台的评分口径不可直接横向比较。

## 3. 住宿区域与路线共同优化

根据本次真实节点比较有现实意义的住宿区域，不只比较行政区或“市中心”。至少评价：

- 到主要景点、固定预约、交通枢纽、一日游集合点的每日门到门时间、换乘和费用；
- 抵达日、离开日、日出前、日落后、夜间活动及拍摄点的可靠交通和安全返回；
- 是否适合从住宿直接开始城市闲逛，街道连续性、步行舒适度、坡度、过街、夜间照明和天气影响；
- 返回住宿后周边仍可步行体验的街区、夜景、市场、便利设施和真正营业的餐饮选择；
- 早餐、晚餐、当地小店、菜市场 / 食品市场、便利店、药店和洗衣等本次生活需求；
- 地铁 / 公交入口、台阶、电梯、行李拖行距离、出租车上下客、自驾停车和充电；
- 夜间噪声、酒吧街、施工、人流、无障碍和同行者能力；
- 房价节省是否会被交通费、时间损耗、无法散步和更高失败风险抵消。

先形成路线骨架，选择住宿区域，再用住宿基点重算每天路线和用餐；如出现大量折返、晚间回程困难或生活体验差，重新选择区域。住宿区不能只用一个综合分数掩盖取舍，应分别说明“路线效率、城市生活、饮食便利、住宿质量、总成本和体验价值”。

## 4. 评价具体住宿

对进入最终短名单的住宿至少核验：

- 准确地址、实际入口、合法经营 / 登记状态和地图可检索名称；
- 当次真实可订房型、入住人数、床型、独立 / 共用卫浴，以及照片是否对应这一房型；
- 入住 / 退房、深夜抵达、前台时段、自助入住、证件登记和行李寄存；
- 电梯、楼梯、空调 / 供暖、隔音、禁烟、热水、网络和无障碍条件；
- 付款时间、支付方式、押金 / 预授权、取消、未入住、改期和平台客服责任；
- 自驾所需停车、限高和充电；徒步所需早餐、装备寄存、烘干、接驳和早退房；
- 从实际入口到车站、景点、餐饮街区和夜间活动的真实步行 / 接驳，而不是只看地图直线距离。

景观房、阳台、特定楼层、连通房或接送只有在具体房型与住宿方确认后才能写为已保证；订单备注请求不能当作承诺。

## 5. 体验型住宿可以成为旅行节点

把住宿区分为：

- `功能型住宿基点`：主要价值是睡眠、交通、生活便利和成本；
- `体验型住宿`：住宿本身具有难替代的景观、建筑、温泉、历史、在地生活、野生动物、摄影或社交发布价值，值得占用正式行程时间。

例如雪山日照金山观景住宿，必须进一步核验：

- 景观是否真正在住宿内可见，还是需要前往公共观景台；
- 哪种具体房型、朝向、楼层、阳台或公共空间可见，是否有遮挡；
- 本次日期的日出方向、季节、天气概率和需要提前到位的时间；
- 宣传图片是否依赖无人机、长焦、重修图、极端天气或并非住客可达的位置；
- 价格溢价、最低入住晚数、取消条件和天气失败后仍保留的住宿价值。

默认减少没有收益的搬迁，但不把“少换住宿”设为绝对目标。当体验型住宿的独特价值、路线衔接、摄影机会或体力收益足以覆盖房价溢价、收拾、退房、行李搬运、等待入住和天气失败风险时，可以主动推荐换住一晚或采用多个住宿基点，并解释为什么值得。若体验只需到访而不需入住，也要比较“入住”和“外出体验”两种方案。

## 6. 比较真实总成本与预订风险

统一计算：

- 房费全程总额，而不是“每晚起”；
- 城市 / 住宿税、度假费、服务费、清洁费、平台费和强制附加项目；
- 早餐、加床、儿童、停车、充电、行李寄存及延迟入住 / 退房费用；
- 押金、预授权、付款币种、汇率、银行卡 / 钱包兼容和境外支付成本；
- 住宿位置和换住产生的公共交通、出租车、机场 / 车站接驳与行李移动成本。

同时写每晚价格和全程住宿总价，标明币种、`每房 / 每人`、是否含税、价格渠道和核验时间。价格随时可能变化，不把核验价写成保证。

费用必须逐项分类，不能把所有到店付款统称为“税费”：

- 法定税、城市 / 旅游 / 住宿税、度假费、强制服务费、清洁费和平台费分别列出；
- 说明每项按人、按房、按晚还是按比例计算，是否已包含在平台显示总价中，以及预订时支付还是到店支付；
- 自愿小费与强制费用分开；已收服务费时说明是否仍存在当地自愿给小费的惯例，避免重复支付；
- 押金和信用卡预授权不是已发生的住宿成本，应注明金额、占用方式、释放条件和预计释放时间；只有被扣留或产生费用时才计入实际成本。

遇到到店价格或退房账单与预订确认不一致时，先索取逐项住宿账单，要求说明收费名称、计算方式和预订条款 / 当地规则依据，再对照平台确认、房型和已付款项目；必要时请值班经理和预订平台共同确认。刷卡前核对金额与币种。现场以人身、证件和行李安全为先，不统一建议直接拒付或冲突；保留订单、账单和支付凭证，再按适用情况使用当地消费者主管机构、旅游警察、平台申诉或发卡行争议流程。

在签证、交通、天气敏感体验或同行人数尚未稳定时，优先展示可取消方案；并列显示不可退款价差、取消截止日期与最大损失，由用户决定是否承担风险。不得引导脱离正规渠道私下转账。

## 7. 住宿质量综合评估

平台评分只作弱初筛，不是推荐依据。对进入短名单的住宿按以下四层综合评估：

**第一层：评分初筛。** 综合评分只用于过滤明显差池，不用于排序；评分量纲因平台而异，不跨平台横向比较。平台默认排序受付费推广、刷评和流量影响，不得直接当作质量顺序。

**第二层：评价挖掘。** 优先阅读近 6 个月、目标房型的中段差评（如 4–6 分）；疑似情绪化或单次事件的极端差评单独打折。把差评按类型统计：硬件型问题（隔音、热水、空调、虫害、网络、电梯）反复出现是强负面信号；服务型与期望型差评单独看待，不与硬件问题混计。同时核验评价者画像——同行者结构、出行目的与本次越接近，参考价值越高；不同客群的评价标准不同，不把单一客群的差评当作全部住客的结论。

**第三层：跨平台三角验证。** 同一住宿在两个以上平台的评分趋势是否一致；一边倒好评而另一平台沉默或明显偏低，视为风险信号。官方展示图与近期住客实拍图对比，识别翻新前旧图、广角畸变和样板间差异；区分旧楼 / 新楼、主楼 / 附楼、装修前后和不同房型，一类房间的评价不套给全部房间。

**第四层：评分卡输出。** 推荐时按固定维度给出证据再合成结论：`路线适配（门到门时间）｜睡眠风险（噪声源证据）｜硬件匹配（本次在意的设施）｜真实总价（含税全程）｜取消弹性｜到店风险（押金、加价、登记要求）`。每个维度标注证据来源与查证时间；综合推荐必须能被用户按维度质疑和调整，而不是一个不透明的总分。用户对某维度有特别要求时，先调权重重算，再解释差异。

只能根据可观察证据写“风险较高”并说明依据；证据不足时不得指控虚假评价或诈骗。

## 8. 交付住宿推荐方案

住宿未订且会影响路线时，必须先给区域结论，再给高匹配的具体短名单：

| 区域 / 住宿 | 方案角色 | 为什么适合本次 | 路线与周边步行 | 在地餐饮便利 | 体验价值 | 同口径全程总价 | 房型 / 权益 | 取消与付款 | 主要风险 | 查询渠道与时间 |
|---|---|---|---|---|---|---|---|---|---|---|

- 区域数量和住宿数量由目的地复杂度决定，不机械固定，也不用低质量长名单制造选择感。
- 最终应给出明确的“综合推荐”，并按实际情况补充“更省钱、交通更优、城市闲逛更好、体验型住宿或风险更低”的替代方案；没有真实差异时不强行凑类别。
- 给出可点击的住宿官方页和可核验的预订平台页面；说明推荐使用哪个渠道以及原因，但不替用户完成不可撤销预订。
- 说明推荐依赖的日期、人数、预算、路线和房型；这些条件变化后重新搜索和比价。
- 住宿已订时，输出“适配性核验 + 对路线、用餐和预算的影响”，不重复生成无关酒店榜单。
