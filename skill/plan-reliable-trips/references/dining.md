# 在地饮食、美食研究与路线安排规则

仅在用户希望体验当地饮食、需要推荐餐厅 / 市场 / 街边小店，或某餐会成为路线锚点和重要取舍时读取本文件。普通路线跨越正餐时仍要保留真实用餐窗口和顺路区域，但不因此自动展开完整饮食研究。

## 1. 先研究吃什么，再研究去哪里吃

- 根据目的地、季节和本次路线建立当地代表菜、日常主食、早餐、小吃、甜品、饮品、市场和区域饮食差异候选。
- 区分“当地人日常吃什么”“节庆或季节限定”“有文化价值但未必适合本次”“主要面向游客的商品”。
- 结合本次饮食限制、预算、接受街边小店程度、排队 / 预约意愿、作息和同行者需要筛选。
- 不为凑数量安排重复菜式；让几顿重要餐分别承担当地饮食的不同体验。

## 2. 用多类来源寻找真正本地化的选择

根据目的地实际可用性组合使用：

- 餐厅、市场或主厨的官方页面、菜单、预订页和当前营业信息；
- Google Maps 的近期评价、普通顾客照片、菜单和问答；
- 目的地当地人常用的地图、点评、预订或外卖平台，并使用当地语言搜索；
- 当地报刊、长期餐饮作者、专业食评、菜系研究和可信本地指南；
- Michelin、Bib Gourmand、Gault&Millau 或当地奖项只在目的地确有参考价值时使用，不把获奖等同于最适合；
- 小红书、短视频、博客和社交平台用于发现候选与近期现场线索，不单独证明品质或“本地人爱吃”。

Google Maps 相对适合跨平台交叉检查，但评分、评论和排序同样可能受到游客结构、营销、刷评或语言偏差影响，不能单独决定推荐。

## 3. 判断“本地人常去”必须有依据

不得仅凭宣传文案写“当地人最爱”。综合检查：

- 当地语言评价的内容、时间分布和近期一致性，而不只看数量与平均分；
- 菜单是否以本地常见菜、当季食材和合理本地价格为主；
- 是否位于居民生活区、办公区、传统市场或长期经营街区，而不只在游客商业带；
- 工作日早餐 / 午餐 / 晚餐的真实客流线索、回头客描述和普通顾客照片；
- 多个相互独立的本地来源是否长期提及，而不是同一营销素材被转载；
- 近期是否发生换主厨、换店址、品质下降、菜单缩水或明显游客化。

这些只能支持“本地客群证据较强 / 混合客群 / 主要游客向”的规划判断，不能假装知道每位顾客身份。

## 4. 餐厅和小店的筛选维度

对进入路线的候选检查：

- `在地价值`：菜式、原料、做法或场景是否具有地方性和不可替代性；
- `实际质量`：近期出品稳定性、招牌菜与普通菜的差异、份量和明显负面反馈；
- `价格价值`：人均区间、法定税、强制服务费、餐位 / 面包 / 饮水费、最低消费、刷卡附加费、可选小费和是否需要现金；不把这些项目混写，也不以高级或便宜自动代表好；
- `路线适配`：从上一节点、下一节点和住宿的真实绕行时间，营业窗口和错过后的替代；
- `等候与预订`：是否必须预约、排队机制、过号规则、用餐时长和迟到政策；
- `饮食适配`：过敏原、忌口、素食、清真、儿童和语言沟通；无法确认时明确保留风险；
- `现场条件`：座位、卫生线索、吸烟、空调 / 户外、厕所和同行者舒适度；
- `信息确认情况`：菜单、价格、营业、店址和预订是否为当前信息。

街边摊、小店、市场档口与普通餐厅可以同等进入候选。对食品安全不凭外观下保证；优先选择周转快、现场烹制、食材保存合理且近期无重复卫生问题的摊位，并在可获得时核验当地卫生评级或监管信息。

## 5. 甄别网红与营销噪音

- 检查大量相同机位、相同招牌菜、同质化“必吃”文案、探店套餐、赠送、返现和未披露合作。
- 比较真实菜单、份量、等候、服务、价格和普通顾客原图，识别只适合拍照但不好吃或严重不值的项目。
- 高热度餐厅若仍有不可替代的菜品或场景，可以保留，但必须说明排队、溢价和更本地化的替代。
- 只有平台热度、没有独立质量与在地价值证据的餐厅，不作为核心推荐。

## 6. 把饮食真正排进路线

- 住宿区评价包含早餐、晚餐、当地小店和夜间步行可达性；不是只数地图上的餐厅数量，而是检查本次用餐时段是否营业、街区是否适合步行和是否真正有在地选择。
- 早餐优先结合住宿周边或当天第一段路线；午餐结合上午与下午区域；晚餐结合最后一个节点、夜间闲逛和安全回住宿。
- 把到店、排队、点餐和用餐计入时间。预约餐厅或不可替代的市场时段可以成为路线锚点；普通一餐不应造成跨城折返。
- 每个重要用餐节点尽量给同一区域的主选与备选，避免售罄、休息、长队或临时关门导致整段路线失败。
- 不强迫每一餐固定一家店。确有高价值或需要预约时给具体餐厅；其他餐次可给“适合区域 + 2–3 个已筛选候选 + 现场选择规则”。
- 美食本身值得专程时，说明独特价值、绕行和等待成本，并把它与景点、住宿和总预算一起权衡。

## 7. 账单、小费与不明收费

税费、小费与各类附加费的通用分类和处理原则由 `international-operations.md` 统一负责；本节只补充餐饮场景的具体执行。

- 针对本次目的地和餐厅，优先核验官方税务 / 消费者信息、餐厅当前菜单与预订条款；近期顾客账单可用于发现待查项目，不能单独证明所有商户都合法或都收费。
- 餐饮场景需要分开的项目：法定税、强制服务费、餐位 / 面包 / 饮水费、最低消费、刷卡附加费和自愿小费；说明比例 / 金额、是否已含标价、是否强制、由谁收取和服务费后是否仍通常另给小费。
- 小费只能作为当地消费惯例说明，不得与向边检、海关、警察或其他公职人员支付的非官方款项混为一谈。
- 出现不明的 5%、10% 或其他附加项目时，不凭比例猜它是税还是小费。建议先索取逐项账单，询问收费名称、强制 / 可选属性及菜单或法规依据，对照点单时看到的价格，并在需要时请经理解释或更正。
- 刷卡前核对终端金额与账单、币种一致；已有服务费时避免无意重复给小费。现场以安全为先，不统一建议直接拒付或发生冲突；保留账单、菜单和付款凭证，再按当地规则联系消费者主管机构、旅游警察、预订平台或发卡行处理。

## 8. 交付方式

先给“本次值得吃什么”，再给落实到每日路线的安排：

| 日期 / 餐次 | 区域与路线关系 | 主选 / 备选 | 推荐菜与在地价值 | 人均、税 / 服务费 / 小费 | 营业 / 预约 / 排队 | 支付与饮食限制 | 为什么相信它 | 信息确认情况 |
|---|---|---|---|---|---|---|---|---|

- 使用当地可检索名称并附地图或预订链接；价格、营业时间和店铺状态注明核验日期。
- 明确哪些结论来自官方菜单，哪些来自本地平台、Google Maps 或规划判断。
- 没有足够证据判断某店“本地人常去”时，改写为可验证的事实，不使用空泛标签。
- 最终摘要说明：代表菜是否覆盖、哪些餐为路线锚点、哪些可现场决定、住宿周边晚餐与失败备选是否可行。
