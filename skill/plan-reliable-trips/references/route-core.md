# 通用路线设计规则

只在任务需要逐日、逐时路线或路线比较时读取。

## 1. 通用时间模型

逐段计算，不用景点数量估算行程：

`总耗时 = 活动 + 移动 + 等待 / 换乘 + 排队安检 + 用餐休息 + 找路寄存 + 缓冲`

- 地图耗时是理想估算，不是到达承诺；长距离和关键预约增加单独缓冲。
- 不使用固定的全天缓冲比例。根据不确定性、迟到后果和恢复难度分别设置：普通可替换节点保持合理弹性；昂贵演出、定时讲解、不可退预约、航班 / 城际车、末班交通、返程日和天气敏感项目必须留足安全缓冲，不能只追求“理论上赶得上”。
- 普通观光旅行在用户没有特别说明时采用 `平衡观光模式`：在本次时间、成本、体力、开放和交通允许范围内尽量覆盖真正高价值的地点，同时保留正常用餐、休息、体验完整度和安全返回，不用低价值填充或过度压缩制造“去得多”。用户明确说度假、休养或海边放松时改为 `度假模式`；明确要求尽可能多看时改为 `高覆盖模式`。
- 规划前不只询问抽象的“松弛 / 平衡 / 紧凑”。先用每日预计出发 / 结束时间、核心体验块、总步行与站立、最早 / 最晚硬预约和连续高强度天数描述拟议强度，作为出发前的重点确认；只有会影响核心路线或昂贵预订时才追问。
- 到达日和离开日先扣除机场 / 车站、行李、入住 / 退房和跨城成本。
- 每天最后一个硬关门节点注明最后入场和关闭时间。
- 计算从最后节点返回住宿或交通枢纽的路线，不能在景点处自然结束。
- 已确认预订作为锚点，其他内容围绕它调整。
- 把节点分为硬锚点、核心体验、可移动节点和有余力再加的节点；遇到延误时先删除低优先级内容，不挤压交通、用餐、休息和安全返回。
- 跨越正餐的路线按 `dining.md` 安排真实用餐窗口；高价值或必须预约的当地饮食可以成为路线锚点，普通餐次优先顺路并准备同区域备选。
- 包含景点、街区、展馆、观景点或徒步景观时读取 `photography.md`，轻量扫描全程并给常规地点可执行拍法；只有发现确有价值的光线、角度或画面时才展开重点点位卡，常规知名景点在文字不足以说明构图时也附参考图，不让摄影自动压过本次核心体验。
- 若地点同时具有重大摄影价值和经独立判断的重大社交发布价值，且新增的时间、费用、体力、安全、拥挤与同行者成本可控，提高其路线优先级；成本明显时并列给出普通游览与拍摄强化方案。
- 目的地或当日以博物馆 / 展馆为核心时按 `museum-visits.md` 计算安检、寄存、中文讲解、馆内移动、认知疲劳和缩短路线，不把大馆当作普通一小时景点。

## 2. 季节与临近天气

- 建立路线骨架时先检查本次季节的日照长度、常见降水 / 高温 / 严寒 / 大风 / 雾、汛期 / 雪季 / 台风季、海况、植被与季节关闭；历史气候只能用于季节判断，不能写成届时预报。
- 日期进入可靠预报窗口后，使用目的地官方或高质量的局地预报和预警更新路线；山地、海岸、沙漠、水上和徒步使用对应局地条件，不能用市中心天气代替。
- 临近出发按风险设置复核节点；普通城市活动可在约 `T-7 天` 与 `T-48 小时` 检查，高风险户外、水上或快速变化天气还要按主管机构更新在前一晚 / 当天复核。具体时间随目的地与活动调整，不机械套用。
- 明确哪些项目受降雨、雷电、大风、高温、能见度、积雪、潮汐、海况或空气质量影响，以及触发 `调整时段 / 对调日期 / 换室内项目 / 缩短 / 取消` 的条件。
- 天气变差时先重排室内外节点、摄影时段和交通，再决定删除；遇到官方关闭、危险预警或条件超出活动标准时不得为了完成行程强行前往。

## 3. 路线节点标准

每个节点至少包含：到达窗口、停留时长、前往方式、预约级别、时间限制、体验重点和退出方案。

预约级别统一为：

- `必须预约`：没有指定票或名额通常无法进入；
- `强烈建议`：可能现场购买，但售罄或长队风险高；
- `可现场决定`：通常不影响整日结构；
- `尚未查清`：当前信息不足。

班次未确定时写可用窗口和最晚选择，不虚构某班车或某一分钟到达。

## 4. 城市漫步与一日游

- 选择清晰主题或空间主轴，避免锯齿折返。
- 用固定开放时段和本次重要体验作锚点，再填充弹性节点。
- 说明顺序、总步行、爬升、强度和主要取舍。
- 用餐需要真实时间窗；确有在地价值或需要预约时推荐具体餐厅，其余餐次给合适区域和已筛选的主备选，不用网红清单占满路线。
- 只为本次真实相关的低体力、季节 / 天气、关闭或误点风险给备选，不默认生成晚出发版本，也不机械为每天复制所有版本；备选必须写触发条件、先删哪个节点、替代什么以及是否影响预约和返回。

## 5. 多日旅行

- 每天围绕区域、主题或交通走廊，跨区必须有明确收益。
- 不连续堆叠高强度项目；根据本次同行者状态安排恢复。
- 先形成路线骨架和候选住宿区域，再主动检索具体住宿并重算路线、周边闲逛和用餐；住宿与路线不匹配时继续调整，不能把住宿留到路线完成后再补。
- 换酒店计入收拾、退房、寄存、移动、等待入住和搬运行李；减少无收益搬迁，但体验型住宿的独特景观、建筑、温泉、在地生活、摄影或路线收益足以覆盖成本时，可以主动采用多住宿基点。
- 标明各日强度、移动量和硬预约；天气敏感日可交换时说明条件。
- 抵达日和离开日按真实可用时间设计，不把“半天”当作固定时长。

## 6. 费用、用餐与备选

- 费用按门票、交通、住宿、餐饮、活动和预留项拆分，说明每人 / 每房 / 每车及税费。
- 动态价格给核验日和区间，不合计成虚假精确数字。
- 路线跨越正餐时主动研究在地饮食；确有独特价值、需要预约或能明显改善路线时推荐具体商户，并核验营业与预约，其他餐次提供可靠区域与主备选。
- 每个硬预约或天气敏感日，给不会引发连锁冲突的替代方案。
- 每日指出最先可以删减或缩短的节点；关键连接失败时给下一步动作，而不只列一个没有交通和时间验证的备用景点名称。
