# 旅行保险必要提醒

仅在 SKILL 的保险专项触发条件成立时完整读取本模块；普通境外任务可在当前范围内给一句必要提醒，无需为此加载全文。默认用户自行决定并购买整体旅行险；不要主动生成产品排名、逐条保单对比或完整保障缺口表，也不要为了保险向用户收集大量信息。

## 1. 只确认最小状态

- 只需知道用户是 `已购买 / 计划自行购买 / 尚未确定`。用户已表示会自行购买时，不重复劝购或追问产品细节。
- 不索取保单号、银行卡、账号、完整病历或身份证件。具体投保资料由用户在保险人正式渠道自行填写。
- 用户没有提供保单原文时，不判断“已经覆盖”或“必然可以理赔”。

## 2. 只提醒本次容易漏掉的额外条件

按当前行程选择真正相关的项目，通常不超过 3–5 条：

- **强制证明**：签证、入境、邮轮、旅行团或活动是否要求保险证明，以及地域、日期、最低项目和证明语言；
- **特殊活动**：高海拔徒步、滑雪、潜水、摩托车、自驾、竞赛、偏远地区、搜救或直升机是否有明确排除、海拔 / 深度上限或资质要求；
- **偏远医疗与撤离**：当地普通医疗之外是否可能需要转诊、撤离或送返；
- **既有病症或孕期**：只有用户说明相关情况时，提醒核验对应条款，不询问完整病历；
- **高额不可退项目**：只有金额确实影响决策时，提醒用户自行考虑取消 / 中断保障；
- **信用卡保障**：只有用户计划依赖时，提醒核验支付启用条件、同行人范围、行程天数和主要排除；
- **租车车辆保障**：按 `self-drive.md` 单独核验，不把 CDW / LDW 当成整趟旅行险。

不维护“哪些国家永远强制保险”的静态清单；强制证明和活动要求按本次日期使用主管机构或运营方原文核验。

## 3. 给出最小使用提醒

- 出发前离线保存保险凭证、24 小时协助电话、紧急 / 预授权步骤和正式报案入口。
- 发生事件时先保证人身安全；安全允许时联系保险协助，并保存医疗账单、承运人证明、报警记录或取消文件等本次需要的材料。
- 不承诺理赔成功，也不建议夸大、改变或伪造事件描述。

## 4. 输出边界

默认只给 `无额外保险提醒 / 有事项需出发前确认 / 用户计划自行处理整体旅行险` 和少量本次提醒，不生成产品推荐或大表格。

只有用户明确要求并提供去敏后的具体条款时，才协助定位与本次活动直接相关的限制；仍需提示以保险人的正式书面答复为准，不替代保险销售、法律或理赔意见。
