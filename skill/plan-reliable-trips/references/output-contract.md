# 条件式输出核心规则

仅在需要交付候选、比较、可执行路线或更新后的旅行方案时读取。专项模块负责本领域的字段和判断；本文件只规定跨任务的最小表达方式，不复述所有模块内容。

## 1. 默认只交付当前问题

- 结论先行：先回答推荐什么、为什么，以及最关键的限制。
- 只显示会影响结论的本次输入、未知和假设；不把内部完整任务卡打印给用户。
- 动态结论在附近给直接来源和查证日期；稳定背景不堆引用。
- 明确仍待确认、出发前复查和会改变方案的条件。
- 不生成未激活模块的章节，不用模板把简单答案扩成完整手册。

## 2. 按任务范围与交付形式组织

核验强度只决定证据要求，不自动增加章节。窄的高后果问题仍可用简短聊天回答。

### 窄问题 + 聊天回答

使用 `结论 → 必要依据 → 下一步或复查点`。能用数段文字解决时不制作大表格。

### 当前方案 + 聊天或结构化计划

按需组合：当前条件、推荐骨架、关键候选、取舍、费用口径、风险 / 未知和下一步。候选数量以支持决定为止，不为凑数固定输出三套方案。

### 综合研究

只有用户明确要求全面展开时，增加统一口径的比较、来源差异、失败条件、敏感参数和精简证据表，并说明重要但未纳入的候选。

### 正式文件

用户确认路线并明确要求文件后，读取 `deliverable-package.md`，从同一权威内容源生成所需视图并执行其中的最终验收。不在早期草案阶段加载或模拟完整交付检查。

## 3. 常用结果结构

### 可执行路线

路线需要逐时表达时可使用：

| 当地时间 | 节点与目的 | 交通 / 步行 | 停留与缓冲 | 预约 / 最晚时间 | 状态与来源 |
|---|---|---|---|---|---|

只增加本次真正需要的住宿基点、用餐、费用、天气、摄影、返程和备选。普通短途或一日骨架不必机械填满所有列。

### 比较

先写选择标准，再用同一口径比较适用条件、完整时间、完整成本、便利摩擦、主要风险和不可逆代价，最后给推荐结论。不同口径的信息不得并排伪装成可比较。

### 最低成行条件

在可执行任务需要时，列出最低条件及 `已满足 / 待确认 / 不满足`，再给 `可行 / 条件可行 / 明显不匹配 / 尚无法判断`。没有明显阻断也要写明待办理和临近出发复查项；快速灵感和纯格式任务不生成这一段。

### 费用

标明币种、`每人 / 每房 / 每车 / 每段 / 全程`、必要或可选、价格时间点和是否含税费。只汇总本次已经研究的主要项目，不为了完整账单猜测缺失数字。

### 备选

只针对真实风险提供备选，并写清触发条件、替换内容及对时间、费用、预约和返回的影响；不复制多套几乎相同的完整日程。

## 4. 最小质量检查

交付前只检查当前激活范围：

- 结论是否直接回答用户当前问题；
- 是否误载或输出了无关模块；
- 日期、时区、人数、币种和比较口径是否一致；
- 关键动态事实是否有适当来源和状态；
- 路线是否计算移动、等待、用餐、缓冲和安全返回；
- 费用是否区分必要 / 可选及单位；
- 不确定项、失败条件和复查节点是否保留；
- 专项内容是否符合当前已加载模块，而不是依靠本文件重复检查所有领域。

除正式交付外，不运行与当前任务无关的全项目检查表。
