# 正式旅行资料包交付规则

路线已进入正式交付，或用户要求 PDF、图片化指引、速查卡、打印版、离线使用及可交给 AI 提问的资料包时读取。早期目的地探索和简单比较不机械生成整套文件。

## 1. 一个权威内容源，多种使用视图

- 以完整 Markdown 手册作为可编辑、可更新的权威内容源；完整 PDF、速查卡和打印应急版均由它派生，不分别维护事实。
- 所有文件使用同一旅行名称、日期范围、版本号、生成日期和最近核验日期。路线或动态信息更新后，同步重新生成受影响的版本。
- 不把同一段信息复制到多个章节；使用目录、内部链接、标签和清晰的交叉引用。

## 2. 默认正式资料包

正式行程通常交付：

| 产物 | 用途 | 默认要求 |
|---|---|---|
| `00_开始这里.md` | 说明各文件用途、当前版本、最近核验日期和怎样继续更新 | 简短，不重复攻略正文 |
| `01_出行速查卡.pdf` | 现场快速看当天安排、地址、入口、预订、支付、返回和紧急信息 | 手机优先；按天分屏 / 分页，不强求压成一页 |
| `02_完整旅行手册.md` | 权威源文件；修改、复核和交给 AI 深入提问 | 文字、表格、图片引用和来源完整 |
| `02_完整旅行手册.pdf` | 手机阅读、搜索、分享、单文件交给 AI 或普通打印 | 有文本层、目录书签、内部链接和图片说明，不是扫描版 |
| `media/` | 保存实际嵌入的摄影参考图、入口 / 换乘定位图和必要示意图 | 文件名可识别，保留来源与查证日期 |

以下内容按需生成，不设为每趟旅行的固定负担：

- `03_打印应急版.pdf`：国外、偏远、徒步、通信不稳或用户明确要纸质备份时生成；
- 单文件离线 HTML：只有用户需要手机交互搜索 / 折叠导航，且能确认设备使用方式时生成；
- 单独的预订或个人证件附件：只有用户主动提供并要求整理时处理，不把护照、完整银行卡等敏感信息默认写入攻略。

交付时可同时提供一个 ZIP 便于保存整套资料，但“把单个文件发给 AI”时优先使用完整 PDF；AI 支持 Markdown 与文件夹时优先提供 Markdown 和 `media/`。

## 3. 完整手册的信息层级

完整手册使用可点击目录和 PDF 书签，保持以下查找顺序：

1. 封面、版本、最近核验日期、本次输入与关键假设；
2. 一页旅行总览：日期、同行者、预算口径、住宿基点、主要交通、已订硬锚点和最高优先级风险；
3. 现在要做的预订 / 准备，以及临行复查时间表；
4. 总体路线、住宿与城市空间关系；
5. 按天路线：每天先给一屏 / 一页概览，再给节点详情；
6. 只保留本次相关的住宿、饮食、交通支付、展馆、摄影、国外、徒步、购物等专题卡；
7. 双语地点与关键话术索引；
8. 关键证据、尚未确定项和复查节点。

每天使用一致结构：`当日结论 → 时间线 → 地点与入口 → 交通 / 支付 → 用餐 → 拍摄 → 预约 / 风险 → 返回与备选`。使用 `[入口] [预约] [支付] [拍摄] [风险] [备选]` 等少量固定标签帮助全文搜索，不使用难以理解的内部术语。

## 4. 速查卡与打印应急版

速查卡不是完整手册的缩小字号版本，只保留现场需要立刻行动的信息：

- 每日时间线、硬预约、建议出发时间和最晚返回；
- 住宿、车站、景点入口、集合点和上下车点的可复制名称 / 地址；
- 门票入口、交通方式、支付媒介、价格参考和失败备份；
- 主用餐与附近备选、关键摄影时段和一句构图提示；
- 当天风险、天气触发条件、紧急联系人和必要当地话术。

打印应急版优先 A4、较大字号、黑白可辨，删除非必要摄影样片和背景介绍；保留航班 / 列车、住宿地址、关键预订、支付备份、紧急求助、徒步退出和无法联网时仍能执行的指引。二维码只能作补充，重要地址与步骤必须同时以文字出现。

## 5. 摄影参考图与定位图片

图片只解决两类文字难以高效说明的问题：

1. `摄影参考图`：用于必拍点和文字不足以解释构图的常规景点。每个重点点位通常 1–3 张，注明来源页面、作者 / 机构（可得时）、查证日期、借鉴的构图、站位 / 朝向、光照与普通游客是否可复现；无人机、长焦压缩、重后期、特殊季节或非公开站位必须标出。
2. `入口 / 换乘定位图`：用于难找入口、正确闸口、站台、集合点、接送上车点、停车入口、博物馆分馆或徒步起点。优先使用官方地图或可核验现场图；必要时在截图上加圆圈、箭头和短标签，同时给地图链接、可复制名称 / 地址、附近地标及现场应寻找的标识。

所有关键内容必须在图片旁另有文字说明和替代文本。截图注明核验日期；入口、施工或标识可能变化时标为出发前复查。无法合法或稳定嵌入原图时，提供来源页与自制简图，不使用来源不明的转载图，也不把个人票券、二维码或证件信息放入示意图。

## 6. 双语名称、标识与现场话术

- 中国以外地点的详情卡给出 `中文名｜当地官方名｜官方英文名（如有）`，另列可直接复制到地图的检索名与当地文字地址。
- 难找入口写出现场标识的精确文字，例如出口号、门名、楼层、站台或柜台名称；不要只给中文意译。
- 按本次场景提供少量可直接出示的双语 / 当地语言话术，例如确认司机目的地与总价、拒绝额外项目、索取收费明细、酒店入住、饮食限制和紧急求助。
- 优先使用机构官方写法或可靠语言来源；未经充分核验的复杂句子标明机器辅助翻译，不用中文谐音替代当地文字。

## 7. 交给 AI 继续提问

Markdown 是最佳的继续编辑与 AI 上下文文件；完整 PDF 必须保证文字可选择、标题层级明确、表格不是图片、图片带说明、链接可点击，确保只上传 PDF 时也能理解大部分内容。

在完整手册开头加入简短 AI 使用提示：

> 这是截至【核验日期】的旅行规划快照。回答时请标出依据的章节；开放、价格、班次、天气、签证和道路 / 步道状态等动态信息不得仅凭本文视为当前有效，需要时应重新联网核验。

用户可以直接询问“明天几点出发”“把酒店地址和司机话术单独列出”“今天下雨应删改哪些节点”“这张入口图要看什么标识”等。AI 回答时引用章节 / 日期，并区分文件事实、当次联网更新和新的规划判断。

## 8. 生成、更新与验收

建议流程：`路线草案 → 用户确认 → 生成正式资料包 → T-7 天更新 → T-48 小时重点复核 → 行中按需调整`。

- 更新时先改权威 Markdown，再重建 PDF 与速查卡，并在交付说明中列出本次变更；
- 生成 PDF 后必须渲染检查目录、分页、表格、中文字体、图片清晰度、链接、页码和手机可读性；
- 检查图片来源和标注、双语名称、入口文字、文件版本是否一致；
- 不把外部链接当作唯一载体：会影响现场行动的地址、时刻、价格单位、支付和安全步骤必须保留在正文；
- 无法生成或验证某种格式时明确说明，不交付只有扩展名正确但不可可靠使用的文件。
