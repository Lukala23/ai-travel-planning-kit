# 正式旅行资料包交付规则

路线已进入正式交付，或用户要求离线手机版、正式手册、打印版、图片指引或可交给 AI 提问的资料包时读取。早期目的地探索和简单比较不机械生成整套文件。

## 1. 一个权威内容源，多种使用视图

- 以 Markdown 手册作为可编辑、可更新的权威内容源；离线手机版和打印版均由它派生，不分别维护事实。
- PDF 是手册的便携转换格式（阅读、搜索、分享），由手册随手转换即可，不作为单独命名和维护的交付物；需要时才转换。
- 所有产物使用同一旅行名称、日期范围、版本号、生成日期和最近核验日期。路线或动态信息更新后，同步重新生成受影响的版本。
- 不把同一段信息复制到多个章节；使用目录、内部链接、标签和清晰的交叉引用。

## 2. 默认正式资料包

正式行程默认只交付两件产物；其余按需追加：

| 产物 | 用途 | 默认要求 |
|---|---|---|
| `01_离线手机版.html` | 出行现场主力：单文件离线网页，手机浏览器打开即用 | 数据驱动、无外网依赖；规范见第 5 节 |
| `02_旅行手册.md` | 权威源文件：继续修改、交给 AI 深入提问、随手转 PDF 分享 | 开头含版本与核验日期块；文字、表格和来源完整 |
| `media/` | 保存实际嵌入的摄影参考图、入口 / 换乘定位图和必要示意图 | 按需存在，无图片需求不创建；文件名可识别，保留来源与查证日期 |

以下内容按需生成，不设为每趟旅行的固定负担：

- `03_打印版.pdf`：唯一的纸质交付物，速查与应急合一（见第 4 节）。仅在用户要纸、需要纸质备份，或前往通信不稳定地区时生成；
- 单独的预订或个人证件附件：只有用户主动提供并要求整理时处理，不把护照、完整银行卡等敏感信息默认写入攻略。

宿主环境无法生成 HTML 或 PDF 时，明确说明限制并交付可用的替代视图，不声称已生成不可验证的文件。

交付时可同时提供一个 ZIP 便于保存整套资料；用户环境支持文件夹时，优先提供手册加 `media/`，便于继续编辑和交给 AI。

## 3. 旅行手册的信息层级

手册开头是版本块（取代独立的说明文件）：旅行名称、日期范围、版本号、生成日期、最近核验日期、本次输入与关键假设、各产物的当前状态。

其后使用可点击目录，保持以下查找顺序：

1. 一页旅行总览：日期、同行者、预算口径、住宿基点、主要交通、已订硬锚点和最高优先级风险；
2. 现在要做的预订 / 准备，以及临行复查时间表；
3. 总体路线、住宿与城市空间关系；
4. 按天路线：每天先给一屏 / 一页概览，再给节点详情；
5. 只保留本次相关的住宿、饮食、交通支付、展馆、摄影、国外、徒步等专题卡；
6. 双语地点与关键话术索引；
7. 关键证据、尚未确定项、复查节点，以及本次规划的事实台账摘要（来源与查证日期）。

每天使用一致结构：`当日结论 → 时间线 → 地点与入口 → 交通 / 支付 → 用餐 → 拍摄 → 预约 / 风险 → 返回与备选`。使用 `[入口] [预约] [支付] [拍摄] [风险] [备选]` 等少量固定标签帮助全文搜索，不使用难以理解的内部术语。

## 4. 打印版（按需）

打印版是唯一的纸质交付物，把原来的速查卡与打印应急版合并为一份。它不是手册的缩小字号版本，只保留两类信息：

**现场立刻行动**：每日主干时间线、硬预约、建议出发时间和最晚返回；住宿、车站、景点入口、集合点和上下车点的可复制名称 / 地址；门票入口、交通方式、支付媒介和失败备份；主用餐与附近备选。

**应急兜底**：航班 / 列车号与航站楼、每晚住宿名称地址电话、紧急联系人、支付备份（哪张卡、多少现金）、徒步或偏远活动的退出方案，以及手机没电、没网或丢失时仍能执行的指引。

版式优先 A4、较大字号、黑白打印可辨，控制在少数几页；删除背景介绍、摄影样片和非必要细节。二维码只能作补充，重要地址与步骤必须同时以文字出现。

## 5. 离线手机版规范

`01_离线手机版.html` 是出行现场的主力交付物，从仓库模板 [assets/trip-mobile-template.html](../assets/trip-mobile-template.html) 生成：保留模板的页面结构、样式和脚本，只替换数据与图片，不重写页面。

**结构约定**：

- 所有行程数据放在页面内独立 JSON 数据块（`meta`：标题、日期、路线、版本与核验日期；`days[]`：每日时间线、交通、住宿、餐厅与提示；`pois[]`：景点详情与攻略），页面脚本按数据渲染；修改内容只改 JSON，不动页面结构。
- 模板头部注释写明每个字段的含义和修改方法；图片放在脚本顶部的图片映射对象中，按槽位命名，不写入 JSON。
- 未研究完成的景点用占位标志标注并显示占位面板，不虚构内容；已研究完成的景点显示完整介绍与当日攻略。

**必备能力**：单文件、无外网依赖、手机浏览器直接打开；tab 切换总览 / 按天行程 / 景点 / 餐厅 / 参考页；每日时间线中的景点可点击跳转详情；深色遮罩保证背景图上文字可读；正文可被系统搜索或页内查找。

**生成流程**：以已确认的手册为唯一事实源，把确认后的内容填入模板 JSON 与图片槽位；生成后在真实手机浏览器上打开验收。

**验收标准**：手机浏览器实际打开无报错；天数与景点数量与手册一致；每个景点链接可达；版本号和最近核验日期写入数据块；文件大小（含图片）不超过 5MB。

## 6. 离线手机版图片规格

图片集中在页面脚本顶部的图片映射对象中，按槽位命名（封面图单独一个键，每日背景图按天编号）；缺失的槽位自动回退为主题色渐变，页面不报错。

| 槽位 | 数量 | 选图逻辑 |
|---|---|---|
| 封面图 | 1 | 本次旅行最具代表性的一张画面 |
| 每日背景图 | 每天 1 张，可缺省 | ① 当日核心景点的实景图（图文强相关优先）② 交通日或无核心景点时用当日所在城市地标 ③ 相邻两天避免使用同一城市的相似画面 |

**来源顺序**：用户自己拍摄的照片 > 可再利用授权图（如 Wikimedia Commons 的 CC 授权）> 官方旅游机构图片（仅个人使用）。不使用来源不明的转载图。

**技术规格**：JPEG、宽 800–1200 像素、单张压缩后不超过 150KB、全部图片总量不超过 3MB；选亮度中等的画面，文字区域由模板内置遮罩保证可读；不用动图。

**降级纪律**：找不到合规且贴切的图就留空槽位，宁可缺图不放错图——放错城市的图比没有图更糟。景点详情页默认不放图（控制体积与加载速度），这是有意设计，不要为填充而增加。

## 7. 摄影参考图与定位图片

`media/` 目录和手册中的图片只解决两类文字难以高效说明的问题：

1. `摄影参考图`：用于必拍点和文字不足以解释构图的常规景点。每个重点点位通常 1–3 张，注明来源页面、作者 / 机构（可得时）、查证日期、借鉴的构图、站位 / 朝向、光照与普通游客是否可复现；无人机、长焦压缩、重后期、特殊季节或非公开站位必须标出。
2. `入口 / 换乘定位图`：用于难找入口、正确闸口、站台、集合点、接送上车点、停车入口、博物馆分馆或徒步起点。优先使用官方地图或可核验现场图；必要时在截图上加圆圈、箭头和短标签，同时给地图链接、可复制名称 / 地址、附近地标及现场应寻找的标识。

所有关键内容必须在图片旁另有文字说明和替代文本。截图注明核验日期；入口、施工或标识可能变化时标为出发前复查。无法合法或稳定嵌入原图时，提供来源页与自制简图，不使用来源不明的转载图，也不把个人票券、二维码或证件信息放入示意图。

## 8. 双语名称、标识与现场话术

- 中国以外地点的详情卡给出 `中文名｜当地官方名｜官方英文名（如有）`，另列可直接复制到地图的检索名与当地文字地址。
- 难找入口写出现场标识的精确文字，例如出口号、门名、楼层、站台或柜台名称；不要只给中文意译。
- 按本次场景提供少量可直接出示的双语 / 当地语言话术，例如确认司机目的地与总价、拒绝额外项目、索取收费明细、酒店入住、饮食限制和紧急求助。
- 优先使用机构官方写法或可靠语言来源；未经充分核验的复杂句子标明机器辅助翻译，不用中文谐音替代当地文字。

## 9. 交给 AI 继续提问

Markdown 手册是最佳的继续编辑与 AI 上下文文件。需要 PDF 时从手册转换，并确保文字可选择、标题层级明确、表格不是图片、图片带说明、链接可点击；用户环境只接受单文件上传时，PDF 或 ZIP 均可作为载体。

在手册开头（版本块之后）加入简短 AI 使用提示：

> 这是截至【核验日期】的旅行规划快照。回答时请标出依据的章节；开放、价格、班次、天气、签证和道路 / 步道状态等动态信息不得仅凭本文视为当前有效，需要时应重新联网核验。

用户可以直接询问“明天几点出发”“把酒店地址和司机话术单独列出”“今天下雨应删改哪些节点”“这张入口图要看什么标识”等。AI 回答时引用章节 / 日期，并区分文件事实、当次联网更新和新的规划判断。

## 10. 生成、更新与验收

建议流程：`路线草案 → 用户确认 → 生成正式资料包（默认离线手机版 + 手册）→ T-7 天更新 → T-48 小时重点复核 → 行中按需调整`；打印版和 PDF 在用户需要时才生成。

- 更新时先改权威 Markdown，再重建离线手机版（以及已生成的打印版），并在手册版本块中列出本次变更；
- 更新以事实台账为复验基线：先复核台账中已过期或标记“出发前复查”的项，不重查全部事实；台账规则见 `source-verification.md`；
- 生成或转换 PDF 后必须渲染检查目录、分页、表格、中文字体、图片清晰度、链接、页码和手机可读性；
- 离线手机版按第 5 节验收标准在真实设备检查；
- 检查图片来源和标注、双语名称、入口文字、文件版本是否一致；
- 不把外部链接当作唯一载体：会影响现场行动的地址、时刻、价格单位、支付和安全步骤必须保留在正文；
- 无法生成或验证某种格式时明确说明，不交付只有扩展名正确但不可可靠使用的文件。
