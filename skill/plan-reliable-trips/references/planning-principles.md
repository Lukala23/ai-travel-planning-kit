# 固定旅行规划约束

本文件只保存不会随目的地、日期和旅行方式变化的规划方法。目的地、预算、同行人、交通方式、兴趣和体力必须来自当次任务卡。

## 1. 单次任务隔离

- 每趟旅行独立读取一份任务卡。
- 不把过去旅行的参数当作长期偏好。
- 空白表示未知，不表示同意默认值。
- 用户更新任务卡后，以最新版整体重算；不要在旧假设上机械打补丁。
- 只有用户明确声明为长期规则时，才写入本文件末尾。

## 2. 搜索景点与体验的固定要求

- 先明确目的地研究边界：行政范围、常用旅行范围和可接受的一日往返范围。
- 同时搜索代表性、小众、季节性、需预约和与本次目标高度匹配的候选；不把网红榜单当作完整候选池。
- 所有目的地轻量扫描博物馆、展馆、纪念馆、遗址馆和专业小馆；国家 / 地区首府、知名城市与历史文化城市提高扫描强度，真正高价值的小馆也进入正式候选。
- 对非中文目的地，同时使用当地可检索名称、官方英文名和必要的当地语言关键词。
- 去重同名地点、景区子景点和重复包装的体验。
- 搜索范围以“足以支持本次取舍”为准；用户要求穷举时再交付完整候选全集。
- 不因一个地点知名就自动纳入，也不因小众就自动推荐。
- 内部候选搜索可以广泛，交付给用户时必须筛选和分级，避免用候选数量制造完整感。

### 营销噪音与可刷分信息检查

把社交网络、榜单、平台评分和点赞量作为发现线索，不作为旅行价值的独立证据。对高热度地点检查：

- 内容是否集中使用相似文案、相同机位、同一滤镜或营销话术；
- 是否存在赞助、赠送、团购、返现、旅行社或商业合作关系，披露是否清楚；
- 高分是否短期集中出现，近期普通游客的文字、原图和负面反馈是否呈现另一种体验；
- 宣传画面是否依赖无人机、长焦压缩、重度修图、封闭区域、付费布景或极短季节窗口；
- 现场真正可体验的内容、空间尺度和合理停留时间，是否配得上排队、门票、绕行和附加消费；
- 不同平台和不同类型来源是否真正独立，而不是转载同一营销素材。

发现异常时，只能写“营销风险高”并说明可观察依据；没有充分证据不得指控商家刷评或造假。若营销声量明显高于实际体验，且没有不可替代价值，降为 `D 不建议纳入`。

## 3. 每个候选必须评价的维度

| 维度 | 必须回答的问题 |
|---|---|
| 旅行价值 | 它有什么不可替代的体验，还是可以被同类替换？ |
| 为什么适合这次旅行 | 明确对应本次的目标、天数、同行人、预算、节奏、交通或硬限制；资料不足时写“尚不能判断” |
| 可达性 | 从本次起点如何到达，真实门到门成本是多少？ |
| 时段兼容 | 开放、最后入场、光线、季节和班次能否嵌入路线？ |
| 预约摩擦 | 必须预约、建议预约还是可现场决定？售罄代价是什么？ |
| 体力摩擦 | 步行、台阶、爬升、排队和携带行李是否合理？ |
| 费用摩擦 | 门票、交通、停车和附加费用是否匹配本次预算？ |
| 风险与退出 | 天气、关闭、误点或体力不足时能否退出和替换？ |
| 信息确认情况 | 哪些当前已查证，哪些出发前要复查，哪些仍不确定？这只说明信息可靠程度，不参与景点价值排名 |
| 摄影与社交发布机会（按需） | 若确有价值，说明是否值得利用光线、角度或沿途机位；社交发布价值看地方辨识度、画面叙事和真实可复现性，不看平台热度；没有明显价值时不强行评价 |

## 4. “便利”必须拆开评价

不得只写“交通方便”或“不太方便”。至少检查：

- 到达入口而不是只到附近区域的门到门时间；
- 换乘次数、班次密度、首末班和错过后的代价；
- 景点入口方向、寄存、行李、无障碍、停车和步行连接；
- 前后节点是否顺路，是否造成折返或等待空档；
- 游览结束后能否安全、稳定地回到住宿或下一交通枢纽。

统一给出便利摩擦等级：

- `低摩擦`：容易嵌入路线，时间与退出方案稳定；
- `中摩擦`：需要特定班次、预约、绕行或额外缓冲；
- `高摩擦`：会占用大量转场时间，失败代价高或退出困难。

摩擦高不代表不值得去；必须说明它是否值得本次付出代价。

## 5. 路线设计的固定要求

- 先写路线逻辑和取舍，再写逐时安排。
- 普通观光旅行未特别说明时采用平衡观光模式：在时间、成本和体力合理的范围内尽量覆盖真正高价值内容，但不以压缩用餐、休息、体验和安全返回换取数量；明确度假或高覆盖需求时按本次要求切换。
- 规划前用每日起止时间、核心体验块、步行 / 站立量、硬预约和连续高强度天数说明拟议强度，作为出发前重点确认；不只让用户解释“松弛 / 平衡 / 紧凑”等抽象词。
- 不使用固定全天缓冲比例；昂贵演出、定时讲解、不可退预约、末班交通、航班 / 城际车和返程必须按迟到后果、不确定性与恢复难度留足安全余量，其他节点保持合理平衡。
- 路线骨架先考虑季节、日照和典型天气风险；进入可靠预报窗口后结合近期局地预报与预警重排时段、室内外项目和日期，并为重大天气影响设置调整、替换或取消条件。
- 过夜旅行按 `accommodation.md` 主动研究住宿区域和具体住宿，并与路线、周边闲逛和饮食共同优化；住宿总价、衍生交通成本和行李搬迁必须进入预算与时间判断。
- 跨越正餐的路线按 `dining.md` 研究当地代表饮食和可靠餐饮选择；优先寻找本地客群证据较强、地方性真实且与路线匹配的餐厅或小店，社交热度只用于发现候选。
- 优化完整体验与可执行性，不优化景点数量。
- 计入交通、换乘、排队、安检、寄存、用餐、休息、找路和缓冲。
- 每日都有明确起点、终点和返回方案。
- 区分硬锚点、核心体验、可移动节点和有余力再加的节点；延误时先删低优先级内容，不压缩用餐、休息、交通和安全返回。
- 固定预约作为锚点；天气敏感项目准备可切换方案。
- 某地点同时具有重大摄影价值和经独立判断的重大社交发布价值，并且新增的时间、费用、体力、安全、拥挤和同行者成本可控时，提高其路线优先级，优先给予合适时段和停留时间；成本明显时给普通方案与拍摄强化方案供选择。
- 明确列出重要但未纳入的候选及原因，避免无意遗漏。
- 地图耗时和模型估算不能写成保证值。

## 6. 信息与决策透明

- 把事实、估算、推断和建议分开。
- 动态事实遵守 `source-verification.md`，在结论附近附直接来源。
- 来源冲突时保留冲突，不用虚假精确数字掩盖。
- 开头说明使用了哪些当次参数、哪些仍未知、哪些是临时假设。
- 结尾给出真正需要用户决定的少数取舍和临行复核项。
