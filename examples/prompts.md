# TravelSpec AI 可复制提示词

把方括号内容替换成自己的信息。无需一次使用所有提示词。

## 1. 从自然语言建立任务卡

```text
使用 $plan-reliable-trips。

我要去【目的地】，日期是【完整日期】，共【人数】人。
已确定：【航班 / 住宿 / 演出 / 其他不可改变项目】。
预算大致是【预算或成本敏感度】。
这次最重要的是【核心目标】。

先不要排路线。请把信息整理成单次任务卡，区分：
已知事实、硬约束、软偏好、未知、临时假设。
只追问会改变安全、可行性、住宿区域、交通骨架或总预算的问题。
```

## 2. 先研究目的地，不急着排日程

```text
请先研究【目的地】的候选全集并筛选。

同时搜索经典地点、高价值小众地点、季节限定、博物馆和需要预约的体验。
不要把平台排名、点赞或网红程度当作价值。
输出 A / B / C 候选，以及少量我可能疑惑为什么没安排的 D 级地点。
同时告诉我住宿区域、交通结构和哪些决定必须先确认。
```

## 3. 生成可执行路线草案

```text
根据已经确认的候选和住宿区域生成路线草案。

计入门到门移动、排队、正常用餐、休息、行李、预约缓冲和安全返回。
普通观光默认平衡模式，但请用每日起止时间、步行 / 站立量、
硬预约和优先删减点描述实际强度。
备选只针对真实风险，写明触发条件和会改动哪些后续节点。
```

## 4. 住宿专项研究

```text
请把住宿作为路线核心重新研究【目的地】。

先比较区域，再比较具体住宿。统一日期、人数、房型、床型、早餐、
取消、税费和币种，给全程真实总价。
同时评价每日景点交通、机场 / 车站衔接、周边闲逛、当地饮食、
夜间返回、噪声和住宿本身的体验价值。
不要按单一平台评分直接推荐。
```

## 5. 国外支付、网络与交通防骗

```text
这是一次前往【国家 / 城市】的国外旅行。

请核验：
1. 公共交通对我的手机、银行卡和国际钱包是否真正可用；
2. 现金需求、换汇 / ATM 费用和抵达后的第一段支付；
3. 漫游、旅行 eSIM、本地 SIM 的设备兼容与主备方案；
4. 机场到酒店、主要包车和特殊交通的正常价格、计价单位与正规渠道；
5. 总价书面确认的当地语言话术；
6. 常见加价、币种偷换、平台外交易或扣留行李风险及求助方式。
```

## 6. 博物馆与中文理解

```text
请研究【目的地】真正值得纳入的博物馆、展馆和小型专业馆。

不要只看名气或馆藏总量，要核验当前实际在展、核心展区开放、
不可替代性、与其他馆的重复度和真实参观时间。
我是中文母语使用者，请核验官方中文标识、语音、App、中文团和私人中文导游，
明确说明是否值得请导游、当前价格与包含项，并给可执行馆内动线。
```

## 7. 摄影与参考图

```text
请扫描整条路线的拍摄机会。

我主要使用手机，最多加便携稳定设备。重点是构图、站位、方向、
光线、人物关系和避开杂乱，不要默认专业相机。
对必拍点和文字难以解释构图的常规景点，提供来源清楚的实际参考图，
说明借鉴什么、普通游客能否复现，以及是否依赖无人机、长焦、重后期或特殊季节。
长时间等待、明显绕行或牺牲核心体验的拍摄，只作为强化方案。
```

## 8. 审核我下载的徒步轨迹

```text
请使用 $plan-reliable-trips 审核我提供的徒步路线文件 / 链接 / 截图。

检查来源、名称、版本、日期、方向、距离、爬升、起终点、轨迹断裂、
异常跳点、错误支线、关闭 / 私人 / 限制路段，以及山屋、水源、
检查站、危险段、退出和接驳。
结合许可、天气、季节、日照、能力、保险、救援和通信，
给出“可用 / 条件可用 / 不建议使用”及必须修正项。
明确说明审核局限，不把它写成安全认证。
```

## 9. 审阅和修改一条长期约束

```text
请只审阅【主题】相关规则，不要先修改。

先说明：
1. 当前规则会让模型实际怎么做；
2. 我的意见属于安全底线、长期硬约束、默认偏好、软偏好还是单次参数；
3. 有没有把随口倾向扩写成僵硬规则；
4. 应修改哪个文件，会影响哪些输出。

然后给简化后的规则文本，等我逐条确认后再修改。
```

## 10. 生成正式资料包

```text
路线和关键选择已经确认。请生成正式旅行资料包：

- 00_开始这里.md
- 01_出行速查卡.pdf
- 02_完整旅行手册.md
- 02_完整旅行手册.pdf
- media/
- 本次需要时生成 03_打印应急版.pdf

所有版本必须来自同一 Markdown 权威源，写明旅行日期、版本、
生成日期、最近核验日期和复查节点。
PDF 必须有文本层、目录书签、内部链接和图片说明，不得是扫描版。
```

## 11. T-7 天更新

```text
请按 T-7 天标准更新这份资料包。

重新核验局地天气、临时关闭、施工、展厅 / 步道状态、餐厅、
主要班次和重要预约。先列出变化和受影响的路线节点，
只修改真正受影响的部分，再同步重建 Markdown、PDF 和速查卡。
```

## 12. T-48 小时重点复核

```text
请按 T-48 小时标准做最后复核。

重点检查天气预警、航班 / 列车 / 轮渡、步道或道路状态、
重要预约、集合点、入口、支付和网络备份。
输出“无需改变 / 必须调整 / 仍需人工确认”，
并明确每个调整对后续交通、用餐、预约和返回的影响。
```

## 13. 旅行中把手册交给 AI

```text
我上传的是截至【核验日期】的旅行手册。

回答时请指出依据的章节。涉及今天的价格、开放、班次、天气、
签证、道路或步道状态时，请重新联网核验。
请区分：
1. 手册原有事实；
2. 当前联网更新；
3. 你基于两者做出的新规划判断。
```

## 14. 当天下雨，重排但不要推翻全程

```text
今天【日期】的天气发生变化。请只重排今天和真正受影响的后续节点。

保护不可退预约、重要交通和安全返回。
说明删除、移动和替换了什么；新的交通与用餐怎样衔接；
哪些摄影、户外或夜间项目改到更合适的日期。
不要无理由重新生成整趟旅行。
```
